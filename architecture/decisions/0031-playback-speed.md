# 0031 클립 배속

Status: accepted
Source: changes/047-playback-speed/spec.md, changes/047-playback-speed/plan.md

## 맥락
영상과 음성 클립에 배속을 지정해야 한다. 기존 편집 모델은 원본 구간과 타임라인 길이를 같은 초 단위로 계산한다. TTS 재생성과 실행 취소에서도 원본과 배속을 보존해야 한다.

## 결정
- 영상·음성의 선택 필드 `speed`를 배속의 정본으로 둔다. 기본값은 1이며 범위는 0.5–2.0이다. 사진·짤·효과음에는 비1 배속을 허용하지 않는다.
- 원본 구간을 보존하고 타임라인 길이를 배속으로 나눈다. 나누기·트림·트랙 이동은 타임라인 오프셋에 배속을 곱해 원본 좌표로 변환한다.
- 영상은 기존 Remotion 공통 경로의 `playbackRate`로 재생한다. 전환의 양쪽 클립은 각각의 배속과 원본 좌표를 사용한다. 0016의 영상·전환 모델을 보완한다.
- 음성은 합성·녹음 후 원본 파일 전체를 ffmpeg `atempo`로 처리한다. 원본 소리와 stems도 영상 배속을 따른다. 미리보기와 내보내기는 같은 WAV와 측정 길이를 사용한다. 0023의 TTS 생성 모델을 유지한다.
- 영상 1의 뒤 클립만 재배치한다. 새 영상 1 끝을 넘는 오버레이는 앞당기거나 자른다. 자막과 독립 음성·효과음의 시각은 유지한다. 자막 편집과 장면 검토의 상한은 프로젝트 끝이다.
- 배속 변경과 필요한 전환·오버레이 조정을 실행 취소 한 번으로 확정한다. 음성은 후처리에 성공한 뒤 확정한다. 캐시 생성은 실행 취소 이력에 넣지 않는다.
- `Project.audioCache`에 원본 식별자·배속별 파일·측정 길이·원본 버전을 둔다. 원본 버전과 처리 버전을 캐시 파일 이름에 포함한다. TTS 원본은 불변 세대 파일로 보존한다. 세션 중 이전 파일을 지우지 않고 프로젝트를 열 때 미참조 파일을 정리한다.

## 결과
- 영상 끝 뒤에 남은 자막·음성은 검은 화면 위에서 계속 재생된다. 앱은 자막 길이를 음성에 맞춰 자동 변경하지 않는다.
- 처리 전 음성 캐시가 없으면 해당 레이어를 무음으로 둔다. 내보내기는 같은 heavy-media 작업 안에서 캐시를 준비한다.
- 배속이 없는 저장 파일은 기존 1배속으로 읽는다. 0.3.x로 새 프로젝트를 다시 저장하면 배속과 캐시 메타데이터를 잃는다. 구버전의 같은 편집 결과 보존은 지원하지 않는다.
- 자동 길이·주파수 검사는 음절 씹힘 감소를 증명하지 않는다. 설치본 청취와 플랫폼별 실행 검사는 별도로 수행한다.
