# 0018 AI: codex(모델·effort 선택, 기본 gpt-6-luna)와 Jev(짤 적합도·강조 상자) 만

## 맥락
U3 는 사용자의 구독 로그인 세션으로 대본을 만들고, 짤 적합도를 판정한다. 사용자는 codex 의 모델과 추론 강도(effort)를 설정 화면에서 고르기를 원한다. 영상 파생 캐러셀은 프레임에서 강조할 대상의 위치를 찾아야 한다. 0009 는 Jev 를 짤 적합도에만 썼다. 구독에서 쓸 수 있는 모델이 바뀌어도 앱을 다시 빌드하지 않아야 한다.

## 결정
- 대본 생성은 codex CLI 로 한다. 모델과 effort 는 설정 화면에서 고르고 `settings.json` 에 저장한다. 기본값은 모델 `gpt-6-luna` 다. 프레임·사진은 `--image` 로 붙인다. 결과는 zod 로 다시 검증한다.
- 설정 화면은 codex 를 쓸 수 있는지(설치·로그인)만 보인다. 실행 파일 경로는 보이지 않고, 찾지 못했을 때만 직접 지정한다.
- 짤 적합도는 Jev(`jev-1.13.0` 고정)로 판정한다. 기본으로 켠다.
- 캐러셀 강조 대상의 상자는 Jev Box(`jev-1.14.0` 고정)로 찾는다. 이 질문은 프레임 이미지 한 장을 TypeSafe 로 보낸다. Jev 를 끄면 보내지 않고 사용자가 상자를 직접 그린다.
- Jev 키는 개발자가 등록한 키를 쓴다. 빌드할 때 `.env` 의 `TYPESAFE_API_KEY` 를 sidecar 번들에 넣고, 키가 없으면 빌드를 실패시킨다. 키는 커밋하지 않는다. Jev 호출이 실패하면 규칙 점수로 대체한다.
- Claude CLI 와 계정 다중 선택은 없다.

## 결과
이 결정은 원격 AI 호출의 범위다. 로컬 모델(bge-m3 0004, MRX 0008, whisper 0007)은 앱 안에서 돌고 이 결정과 별개다. 사용자는 codex 를 설치하고 로그인해야 한다. 앱은 시작할 때 `codex login status` 로 확인한다. 고른 모델을 codex 가 받지 않으면 대본 생성이 실패하고 이유를 보인다. 설치 파일을 받은 사람은 Jev 키를 꺼낼 수 있다. 외부 배포 전에 키를 서버 뒤로 옮긴다.
