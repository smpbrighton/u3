## 열린 질문에 대한 답
- 장면 고르기: codex 가 프로젝트의 대본 장면 목록(번호·자막)·자막 레이어 메인 줄 글·타이틀을 읽고 장 수(2~10, 기본 5)만큼 대본 장면 번호를 고른다. 엔진이 장면 번호를 그 장면의 영상 1 본 화면 클립 가운데 시각(타임라인 기준)으로 바꾼다. codex 는 시각을 직접 내지 않는다. 사용자는 장마다 시각 슬라이더로 프레임을 바꾸고, 장을 더하거나 지운다. 이유: 처음부터 사용자가 고르면 단독 방식보다 손이 더 간다.
- 강조 효과: 두 가지 길을 둔다.
  - 상자 강조(기본): Jev Box 로 대상의 상자를 찾고, 앱이 원본 프레임 위에 그린다. 형태는 테두리(둥근 사각, 색·두께), 주변 어둡게, 확대 셋이다. 원본 픽셀은 바뀌지 않는다.
  - 윤곽 강조(AI): codex image_gen 에 프레임을 참고 이미지로 넣고 「<대상>에 흰 윤곽 테두리」를 요청한다(0015 의 생성 경로에 `-i` 를 쓴다). 대상의 실제 윤곽을 따라 그린다. 그림 전체를 다시 그리므로 상품 글자·얼굴이 원본과 달라질 수 있다. 화면에 이 사실을 알린다.
  - 이유: 사용자의 예(상품과 손에 테두리)는 윤곽 강조가 가장 가깝다. 원본을 지켜야 하는 장(상품 글자)도 있으므로 원본을 지키는 상자 강조를 기본으로 둔다.
- 강조 대상: codex 가 장면을 고를 때 장마다 대상 문장(예: 「손에 든 상품과 손」)을 함께 낸다. 사용자는 고쳐 쓸 수 있다.
- 원본 영상과의 관계: 만들 때의 스냅숏이다. 프레임은 만들 때 뽑아 캐러셀 폴더에 저장한다. 영상을 고쳐도 캐러셀은 바뀌지 않는다. 「프레임 다시 뽑기」는 원본 프로젝트의 지금 타임라인에서 뽑는다. 원본 프로젝트가 없으면 이 버튼을 끄고 이유를 보인다.

## 요구사항
1. 영상 프로젝트의 스튜디오 머리 줄 버튼과 홈 카드 Menu 에 「캐러셀 만들기」가 있다. 누르면 장 수(2~10, 기본 5)와 비율(설정값)을 정하고 만든다.
2. codex 가 장마다 대본 장면 번호, 제목, 본문, 강조 대상을 낸다. 글은 그 영상의 타이틀과 자막 레이어(모든 레이어의 메인 줄, 032)를 바탕으로 한다. 프레임 이미지는 보지 않으므로 강조 대상은 장면 자막에서 추정한 후보이고, 사용자가 고친다. 결과는 zod 로 검증한다.
3. 엔진이 장마다 그 시각의 영상 1 화면을 1080×1920 으로 뽑아(자막·영상 2 이상·브랜드 요소 없이, 영상 1 이 그 시각에 짤이면 가장 가까운 본 화면 클립으로 옮김) 자르지 않은 채 저장한다. 비율에 맞춘 자르기는 합성 때 `cropY`(0~1)로 한다. 사용자는 세로 자르기 위치를 슬라이더로 바꾼다. 상자 좌표는 1080×1920 프레임 기준 정규화 값이다.
4. 장마다 강조 효과를 「없음 · 테두리 · 주변 어둡게 · 확대 · AI 윤곽」 중에서 고른다. 상자 강조 셋은 Jev Box 결과로 바로 그려지고, 상자 위치를 미리보기에서 끌어 고칠 수 있다. AI 윤곽은 codex 생성 작업으로 돈다(030 의 이미지 전용 큐·상태·다시 만들기를 쓴다).
5. 장마다 시각 슬라이더로 다른 프레임을 고르고 「프레임 다시 뽑기」로 바꾼다. 바꾸면 그 장의 강조 상자를 다시 찾고, AI 윤곽 결과는 버린다.
6. 제목·본문·텍스트 위치 편집, 미리보기, 모두 받기, 목록 저장은 030 과 같다. 목록 카드에 「영상에서」 표시가 있다.
7. 원본 프로젝트를 지워도 파생 캐러셀은 남는다(프레임을 이미 저장했다).
8. Jev 를 쓸 수 없으면 상자 강조를 자동으로 찾을 수 없다고 알리고, 사용자가 상자를 직접 그리게 한다.

## 설계
- 데이터(030 의 `Carousel` 을 넓힌다): 파생 캐러셀은 `topic`·`style`·장의 `imagePrompt` 가 없다. 030 스키마에서 이 셋을 `source.kind = "topic"` 일 때만 필수로 바꾼다. `source: { kind: "topic" } | { kind: "project", projectId, projectName }`. `Slide.background: { kind: "generated", image? } | { kind: "frame", sec, cropY, frame: { file }, highlight?: { style: "border" | "dim" | "zoom" | "ai-outline", target, box?: Box, color?, width?, image? } }`. 030 형식의 캐러셀은 `source.kind = "topic"`, `background.kind = "generated"` 로 읽는다. 쓰기 규칙은 030 을 따른다: 엔진만 `frame`·`highlight.box`(자동 찾기 결과)·`highlight.image`·`status`·`error` 를 쓴다. 사용자의 값(`sec`·`cropY`·`style`·`target`·`color`·`width`, 손으로 고친 상자)은 장 단위 PATCH 로 보내고 엔진이 잠금 안에서 병합한다. `status` 는 그 장의 배경 작업(프레임 뽑기·상자 찾기·AI 윤곽 또는 030 의 그림 생성) 하나의 상태다. AI 윤곽 결과는 버전 파일로 저장하고 새 결과가 성공하면 이전 파일을 지운다. 생성 옵션은 설정의 이미지 옵션(030)을 쓴다.
- 기획(engine): 030 의 기획 실행기에 출처별 지시문과 스키마를 둔다. 파생 지시문은 프로젝트의 장면(대본)·자막 레이어 글·타이틀·영상 길이를 넣는다. 프레임 이미지는 넣지 않는다(codex 호출을 가볍게 둔다).
- 프레임(engine): 영상 1 만 남긴 Timeline 으로 `U3Short` 의 그 프레임을 renderStill 로 뽑는다. 미리보기와 같은 9:16 맞춤(가로 영상 포함)이 그대로 나온다. 장면 번호 → 영상 1 클립 → 타임라인 시각 변환은 새 순수 함수로 만든다.
- 대상 찾기(engine): `src/core/jev-api.ts` 에 Box 질문 타입을 더하고, 엔진에 이미지를 붙여 보내는 Jev 요청(multipart)을 만든다. 모델은 `jev-1.14.0` 고정이다(0018). 형식은 TypeSafe 공식 문서로 확인한다. confidence 가 낮으면 상자를 비우고 직접 그리게 한다.
- AI 윤곽(engine): 030 의 이미지 실행기에 참고 이미지(`-i`)와 별도 지시문을 넘긴다. 지시문은 「원본의 사람·상품·글자를 그대로 두고 <대상>에만 흰 윤곽 테두리를 더한다」이고 「글자 없음」을 넣지 않는다. 0015 의 「글자 없는 배경」은 단독 방식의 생성 그림에만 쓴다.
- 합성: 030 의 `CarouselSlide` 가 배경 종류와 강조(테두리·어둡게·확대)를 그린다. 미리보기와 받기가 같은 컴포넌트를 쓴다. AI 윤곽 결과는 배경 그림을 바꾼다.
- API: `POST /api/projects/:id/carousel`(파생 캐러셀 만들기 작업), `POST /api/carousels/:id/slides/:slideId/frame { sec, cropY }`, `POST /api/carousels/:id/slides/:slideId/highlight { style, target, box?, color?, width? }`.
- 화면: 장 편집 패널에 「배경」 절(시각 슬라이더, 자르기 위치, 강조 형태 Segmented, 대상 TextField, 색·두께)을 더한다. 미리보기에서 상자를 끌어 고친다(032 의 편집 층 방식).

## 결정
- Jev 는 짤 적합도(`jev-1.13.0`)와 캐러셀 강조 상자(Box, `jev-1.14.0`) 두 쓰임이다. Box 는 프레임 이미지를 TypeSafe 로 보낸다. 0009 를 대체한다 → [0018](../../decisions/0018-codex-jev-box.md)
- 캐러셀은 단독(주제)과 영상 파생 두 방식이다. 파생은 영상 프레임을 배경으로 쓰고 상자 강조(Jev Box)와 AI 윤곽 강조(codex image_gen 편집)를 둔다. 0014 를 대체한다 → [0017](../../decisions/0017-scope-carousel-two-modes.md)

## 우려 사항
- AI 윤곽 강조는 프레임 전체를 다시 그린다. 상품 상표 글자·얼굴이 원본과 달라질 수 있다. 정책 소유자: 사용자. 추천: 기본은 상자 강조로 두고, AI 윤곽을 고르면 「원본이 다시 그려진다」는 안내를 보인다. 이유: 상품 리뷰 콘텐츠는 상품이 정확해야 한다.
- 프레임 한 장을 TypeSafe(Jev Box)와 codex(AI 윤곽)로 보낸다. 사람 얼굴이 담긴다. codex 로 프레임을 보내는 것은 대본 생성과 같은 경로이지만, TypeSafe 로 이미지를 보내는 것은 새 경로다(지금 Jev 요청은 글만 보낸다). 정책 소유자: 사용자. 추천: 이대로 가고, 설정의 Jev 켜기/끄기로 막을 수 있게 한다. 이유: 끄면 상자를 직접 그리면 된다.
- U3 의 `jev-api.ts` 는 지금 Box 질문을 쓰지 않는다. Box 의 요청·응답 형식은 smp:computer 의 사용례만 확인했다. 정책 소유자: 개발자. 추천: plan 의 첫 단위에서 TypeSafe 공식 문서로 형식을 확인하고 실제 프레임 1장으로 시험한다.
- 이 변경은 030 과 032 가 병합된 뒤에 구현한다. 이 워크트리는 030 브랜치 위에서 시작했다. 정책 소유자: 개발자. 추천: 030·032 병합 뒤 main 에 rebase 하고 구현한다.

## 검증 기준
- `pnpm verify` 가 종료 코드 0 이고 마지막 줄이 `✓ verify passed` 다.
- 테스트(vitest, 가짜 codex·Jev):
  - 030 형식 캐러셀이 topic·generated 로 읽힘
  - 파생 기획 결과 검증
  - 타임라인 시각 → 영상 1 입력 시각 변환
  - 자르기 위치 계산
  - Box 응답 → 상자, confidence 가 낮으면 빈 상자
  - 강조 형태별 합성 입력
  - 프레임 다시 뽑기가 다른 장을 바꾸지 않음
  - 원본 프로젝트 삭제 뒤에도 캐러셀 읽힘, 「프레임 다시 뽑기」는 거부
  - 장면 번호 → 타임라인 시각, 짤 클립이면 가장 가까운 본 화면으로
  - 손으로 고친 상자가 엔진 병합 뒤 남음, Jev 꺼짐이면 상자 비움
  - AI 윤곽 지시문에 「글자 없음」이 없음
- 실제 확인(개발자 1회, 앱 창 캡처):
  - 실제 영상 프로젝트에서 5장 파생
  - 1장 테두리 강조
  - 1장 AI 윤곽 강조
  - 모두 받기
