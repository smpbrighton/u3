# Spec: playback-speed
Source: intent.md (draft, 같은 턴의 초안). Status: accepted.

## 열린 질문에 대한 답
1. **Q1 대상:** 영상 1·영상 2 이상의 원본 영상 클립과 음성 트랙(TTS·녹음·불러온 음성)이다. 원본 소리·분리한 목소리·배경은 그 영상의 배속을 따른다. 사진·짤·효과음·프로젝트 전체 재생 속도는 제외한다. 짤은 `Loop` 반복이라 배속의 뜻이 다르다.
2. **Q2 범위:** 0.5–2.0배, 입력 간격 0.05, 기본 1.0. 서버는 범위 안의 유한한 수만 받는다. 2 초과는 ffmpeg `atempo` 의 sample skip 경로라 막는다.
3. **Q3 시각:** 영상 클립의 원본 구간은 그대로 두고 재생 길이만 바꾼다. 영상 1 은 뒤 클립을 빈틈 없이 재배치한다. 자막·겹친 영상·음성·효과음의 시각은 바꾸지 않는다(사용자가 손으로 둔 배치를 앱이 판단할 수 없다). 안내 문구는 두지 않는다(화면 글 규칙). 새로 받아 적는 자막은 배속을 반영한다.
4. **Q4 재생성:** TTS 「다시 만들기」는 기존 배속을 유지하고 새 원본에 후처리를 다시 적용한다.
5. **Q5 청취 판정:** 자동 검증은 길이(원본/배속 ±1%)·피치 유지·원본 보존이다. 음절 씹힘 감소는 사용자가 같은 문장을 1.0·1.25·1.5·2.0 배로 들어 판정한다. 후처리는 원본에 없는 음절을 만들지 않는다.
6. **Q6 구버전:** 배속 필드가 없는 프로젝트를 새 버전이 1배속으로 읽는 호환만 보장한다. 0.3.x 가 새 프로젝트를 열면 배속을 무시하고 재저장 때 잃는다.

## 요구사항
1. 사용자는 지원하는 영상 클립 또는 음성 클립 하나를 선택하고 Inspector의 「배속」 한 줄에서 값을 바꾼다. 기본 표시는 `1.00×`다. 지원하지 않는 사진·짤·효과음에는 배속 입력을 보이지 않는다.
2. 배속 변경은 선택 클립에만 적용한다. 영상에 종속한 원본 소리·분리한 목소리·배경은 영상과 같은 배속을 사용한다. 별도의 음성 클립은 영상 배속으로 자동 가속하지 않는다.
3. 영상 클립의 원본 구간은 유지한다. 4초 원본 구간은 2배속에서 2초, 0.5배속에서 8초를 점유한다. 영상 1은 뒤 영상과 빈틈 없이 이어진다. 영상 2 이상의 클립은 기존 시작 시각을 유지한다.
4. 권고안 Q3을 채택하면 기존 자막과 독립 클립의 시각은 그대로다. 영상 1 배속 입력 옆 안내는 “영상 길이가 바뀌어요. 자막과 다른 클립의 시각을 확인해 주세요.”로 한다. 자동 자르기·무음 삽입·자막 늘리기는 하지 않는다.
5. 음성은 합성·녹음이 끝난 뒤 ffmpeg로 후처리한다. 배속만 바꾸면 `u3-tts`를 실행하지 않는다. 피치를 유지하며, 미리보기와 MP4가 같은 후처리 음성을 사용한다.
6. 음성 배속 변경은 시작 시각·자막 길이·장면 길이를 바꾸지 않는다. 후처리한 음성이 자막보다 길면 기존 「!」 경고를 유지하고, 짧아지면 해제한다. 경고를 없애려고 음성을 자동으로 자르지 않는다.
7. 처리 중에는 상태와 취소 동작을 제공한다. 성공 전에는 이전 배속과 파일을 유지한다. 실패·취소·선택 변경·오래된 응답은 현재 클립에 부분 적용하지 않는다.
8. 확정한 배속 변경 한 번은 실행 취소 한 번이다. 실행 취소와 다시 실행은 배속·길이·전환 조정·후처리 참조를 함께 복원한다. 캐시 생성이나 처리 상태만으로 이력을 추가하지 않는다.
9. 저장 후 다시 연 프로젝트는 같은 배속으로 재생한다. 캐시가 없거나 원본이 바뀌면 재생·렌더 전에 다시 준비한다. 캐시가 준비되지 않았을 때 1배속 음성을 새 배속인 것처럼 재생하지 않는다.
10. 배속이 없는 프로젝트는 기존 길이·전환·자막 모양을 유지한다. API와 저장 파일은 허용하지 않는 배속 값을 거절한다.

### 데이터와 시간 단위
- 배속은 클립별 선택 필드 `speed?: number`로 저장한다. 값이 없으면 1이다. 명시적 1은 저장 시 생략해도 된다. 원본 영상의 `inStartSec`·`inEndSec`와 음성의 `file`·원본 구간은 배속 전 좌표로 유지한다.
- 배속은 원본 영상형 VideoClip·OverlayClip과 음성 AudioClip에 적용한다. 공용 AudioClip 정의 때문에 효과음에도 필드가 들어가더라도, Timeline 검증은 효과음의 비1 배속을 거절한다. 사진·짤의 비1 배속도 거절한다.
- 영상의 타임라인 길이는 `(inEndSec - inStartSec) / speed`다. 음성도 같은 계산을 기본으로 하며, 후처리 뒤에는 ffprobe로 측정한 실제 길이를 미리보기·렌더·경고가 공유한다. 측정 길이와 캐시 참조는 원본 식별자·구간·배속에 묶인 선택 메타데이터로 저장한다. 매칭되지 않는 메타데이터는 사용하지 않는다.
- 새 음성 메타데이터가 있어도 `file`은 배속 전 원본을 가리킨다. 후처리 파일을 원본인 것처럼 다시 후처리하지 않는다. 캐시 파일의 0초는 선택한 원본 구간의 시작이다. 렌더에 넘길 때 소스 오프셋을 0으로 바꾼다.
- 자르기 위치가 타임라인의 `t`이고 클립 시작이 `S`이면 원본 자르기 위치는 `inStartSec + (t - S) * speed`다. 트림과 트랙 간 이동에도 같은 변환을 적용한다. 원본 범위 검사는 배속 전 파일 길이로 한다.
- 30fps 변환은 기존과 같이 절대 경계를 반올림한 뒤 차이를 구한다. 0프레임이 되는 편집은 거절한다. 모든 클립 길이를 먼저 반올림해 더하면서 누적 오차를 만들지 않는다.
- 전환은 타임라인 초 단위다. 배속으로 짧아진 클립의 절반을 넘는 전환은 같은 변경 안에서 줄인다. 허용 최소 0.1초보다 짧아지면 해당 전환을 없앤다. 자막의 글·레이어·스타일·강조 표기와 0.3초 등장 효과는 바꾸지 않는다.

### (a) 영상 배속 후보
| 후보 | 길이·미리보기·렌더·자막 영향 | 판단 |
| --- | --- | --- |
| A. 공통 변환에 배속을 추가하고 Remotion `Video.playbackRate`를 사용한다. | 원본 구간은 유지하고 점유 길이를 나눈다. 미리보기와 MP4가 같은 시간 변환을 사용한다. 원본 소리·stems에는 별도 처리가 필요하다. | 권고한다. 현재 Remotion 공통 경로를 유지한다. |
| B. ffmpeg `setpts=(PTS-STARTPTS)/speed`로 새 영상을 만든다. | 미리보기도 이 새 파일을 써야 일치한다. 영상 재인코딩·저장 공간·대기 시간이 추가되고, 원본 구간과 캐시의 매핑이 필요하다. 렌더 때만 적용하면 미리보기와 다르다. | 이번 변경에는 권고하지 않는다. 별도 영상 후처리 없이 기존 경로로 배속을 표현할 수 있다. |

- RenderVideoSequence·RenderOverlay에 클립 배속을 전달한다. 원본 시작 프레임은 원본 좌표다. 일반 영상과 오버레이의 `Video`에 이 배속을 전달한다.
- 전환의 0.5는 클립 배속이 아니라 기존 경계 샘플링 계수다. 양쪽 클립의 배속이 다를 수 있으므로 전환의 from/to에 각각 원본 시작과 재생률을 갖게 한다. 원본 이동량은 타임라인 프레임 이동량에 해당 클립 배속을 곱한다. 기존 1배속 전환의 출력은 유지한다.
- 영상은 계속 muted로 두고 원본 소리·stem-voice·stem-bg를 별도 오디오 레이어로 만든다. 각 레이어는 영상의 배속을 상속한다. 소리가 없는 영상에는 오디오 후처리를 만들지 않는다.
- 영상 1은 배속 반영 길이로 뒤 영상의 시작을 다시 계산한다. 영상 2 이상은 `startSec`를 유지한다. 오버레이 배속으로 길어지거나 영상 1 배속으로 본 영상이 짧아져 기존 오버레이가 영상 1 끝을 넘으면 변경을 거절하고 트림을 안내한다. 독립 클립의 시각을 보존한다는 이유로 오버레이를 조용히 잘라내지 않는다.
- 자막 시각 후보는 ① 기존 시각 유지와 안내, ② 변경 구간 내부 시각을 비례 변환하고 뒤쪽 시각을 이동하는 자동 보정이다. 권고안 ①은 수동 자막을 보존하지만 동기화 작업이 남는다. ②는 대본에서 만든 자막에는 유리하나, 구간을 가로지르는 음성·겹친 영상과 수동 배치의 정책이 필요하다. `sceneIndex`는 모든 클립에 없고, 이어지는 여러 장면이 영상 하나로 합쳐지므로 연결 근거로 충분하지 않다([0013](../../decisions/0013-generation-merge-clips-memes.md), [0029](../../decisions/0029-scene-review.md)).
- `src/core/transcript.ts`의 원본 영상·음성 단어 시각은 `S + (wordTime - inStartSec) / speed`로 옮긴다. 이미 배속한 캐시를 받아 적은 경우에는 다시 나누지 않는다. 받아 적기 라우트가 원본과 캐시 중 무엇을 입력했는지 명시한다.

### (b) 음성 배속 후보와 파일 준비
| 후보 | 품질·미리보기·경고·저장 영향 | 판단 |
| --- | --- | --- |
| A. 원본 구간을 ffmpeg atempo로 후처리한 새 WAV를 만들고 양쪽에서 사용한다. | 피치 유지 처리를 한 번 수행한다. 실제 길이를 측정할 수 있고 브라우저별 배속 차이를 피한다. 캐시·실패·취소 처리가 필요하다. | 권고한다. 사용자가 허용한 생성 후 후처리다. |
| B. MP4 렌더 때만 atempo를 적용한다. | 원본은 보존하지만 미리보기와 소리가 다르다. 경고도 최종 길이와 달라질 수 있다. | 거절한다. 같은 미리보기·렌더 규칙을 만족하지 못한다. |
| C. 미리보기와 렌더의 Audio에 playbackRate만 준다. | 저장 공간은 줄지만 피치 보존과 플랫폼별 출력 일치를 별도로 해결해야 한다. | 현재 버전에서는 권고하지 않는다. `package.json`은 Remotion 4.0.529를 고정한다. 공식 문서의 `@remotion/media` preservePitch는 4.0.538 추가 기능이므로 그대로 쓸 수 없다. |

- 엔진에 공통 오디오 준비 서비스를 둔다. 입력은 프로젝트 안의 원본 식별자, 원본 구간, 배속이다. 결과는 후처리 WAV의 프로젝트 상대 경로·실제 길이·원본 버전 키다. Preview와 renderShort가 같은 서비스를 사용한다. 기존 인증된 loopback 미디어 경로로 제공한다.
- 새 API는 원본 절대 경로를 클라이언트에서 받지 않는다. 프로젝트와 클립 식별자로 원본을 찾는다. 저장된 배속과 다른 미확정 값을 준비할 때는 범위 검증과 원본 버전 검사를 먼저 한다.
- 처리 순서는 원본 구간 추출(`atrim`), 시각 초기화(`asetpts=PTS-STARTPTS`), `atempo=speed`, WAV 출력, ffprobe 검사다. 1배속은 원본을 그대로 사용한다. 필터를 두 번 적용하거나 `asetrate`로 피치를 함께 바꾸지 않는다.
- 캐시 키는 원본 내용 버전, 원본 구간, 배속, 출력 형식과 처리 버전을 포함한다. TTS가 같은 경로에 새 내용을 쓰면 새 키를 사용한다. 파일 이름만 같다는 이유로 이전 음성을 재사용하지 않는다.
- 프로젝트 내부 캐시에 임시 파일을 만들고 전체 성공 뒤 최종 경로로 옮긴다. 처리 실패·취소는 임시 파일만 지운다. 원본·이전 캐시·현재 클립을 바꾸지 않는다. 프로젝트 삭제 전에는 이력에서 참조하는 파일을 정리하지 않는다.
- TTS 재생성도 원본 버전과 후처리 파일을 불변 세대별 경로로 보존한다. 현재 고정 파일명 교체만 유지하면 실행 취소와 캐시가 이전 원본을 재현하지 못한다. 클립에 넣는 파일 경로를 결과에 포함하므로 UI는 새 경로를 사용할 수 있다.
- 후처리는 heavy-media 작업으로 직렬화하고 AbortSignal로 ffmpeg를 취소한다. 내보내기 작업 안의 캐시 준비는 같은 작업에서 실행한다. 잠근 heavy-media 작업을 다시 시작해 자신을 기다리게 하지 않는다. 외부 TTS·음성 분리와의 동시 실행 금지는 유지한다.
- 성공한 결과만 Timeline 변경 한 번으로 반영한다. 요청 당시 클립·원본 버전·배속과 현재 상태가 다르면 결과를 적용하지 않는다. 렌더 시작 시점의 Timeline과 준비 파일을 고정한다.
- 원본 소리와 stems도 같은 준비 경로를 쓴다. 전환이 요구하는 원본 오프셋·재생 길이·핸들을 포함해 처리 구간을 구한다. WAV를 재생할 때 Remotion의 추가 playbackRate는 1이다. 프레임 오프셋도 처리 파일 좌표로 바꿔 이중 배속을 막는다.
- ffprobe의 실제 길이와 `(원본 구간 길이 / speed)`의 차이를 검사한다. 한 프레임(1/30초)을 넘는 차이가 나오면 후처리를 실패로 처리하고 필터·구간 처리를 조사한다. 음절을 잘라 이 오차를 숨기지 않는다. 타임라인·렌더·경고는 성공한 처리 결과의 같은 길이를 사용한다.
- `ttsOverflow`는 대응 자막에 대한 유효 재생 길이를 비교한다. 기존 0.001초 허용값을 유지한다. 경고는 자막 초과 표시이며 다음 음성과의 실제 겹침 판정이라고 단정하지 않는다. Inspector 안내도 「자막보다 음성이 길어요」로 맞춘다. 음성이 길어 프로젝트 끝이 늘어나는 현재 동작은 유지한다.

### (c) Inspector
- 기존 PropertyRow 한 줄에 「배속」 label, 수치 입력, 현재 값(`1.25×`)을 표시한다. 새 카드나 설정 화면을 만들지 않는다. 32px 컨트롤과 다크·라이트 테마 규칙을 유지한다([0025](../../decisions/0025-ui-shadcn.md)).
- 수치 입력은 로컬 초안이다. Enter 또는 blur로 확정하고 Escape로 되돌린다. 빈 값·범위 밖 값은 오류를 표시하며 Timeline을 바꾸지 않는다. 같은 값 재확정은 이력을 만들지 않는다.
- 음성 처리는 입력 확정 후 시작한다. 처리 중에는 이 행에 상태를 표시하고 해당 입력을 잠근다. 기존 작업 진행·취소 UI를 사용한다. 성공 전에는 이전 배속을 현재 값으로 표시한다.
- 다중 선택과 묶음 일괄 배속은 이번 범위 밖이다. 단일 클립 배속은 묶음의 다른 클립을 바꾸지 않는다. 원본 소리를 선택한 경우에는 영상 배속을 읽기 전용으로 표시하고 해당 영상 선택을 안내한다.

### (d) 실행 취소와 저장 호환
- `src/core/timeline/history.ts`의 100개 스냅숏을 유지한다. 영상 배속과 필요한 전환 축소를 하나의 새 Timeline으로 만든다. 음성은 후처리 성공 후 배속·실제 길이·캐시 메타데이터를 한 번에 반영한다.
- 후처리 파일은 불변이다. 실행 취소가 이전 배속을 복원할 때 이전 파일을 다시 쓸 수 있어야 한다. TTS 재생성도 이전 원본을 삭제하지 않는다.
- 새 필드는 모두 선택적이다. 기존 `captions` → `captionLayers` 변환과 `sceneIndex` 복원은 유지한다. 배속 없는 기존 프로젝트의 재생 시간과 JSON 구조를 불필요하게 바꾸지 않는다.
- 0.3.x의 schema에는 배속과 새 메타데이터가 없다. 현재의 객체 파싱·재직렬화 경로는 알 수 없는 필드의 보존을 보장하지 않는다. 구버전은 원본을 1배속으로 해석하고 다른 길이를 계산하며, 재저장하면 배속 정보를 잃는다. “파일을 읽음”과 “같은 편집 결과를 보존함”은 구분한다.
- 배속을 처리한 WAV를 기존 `file`에 대신 저장하면 음성만 구버전에서도 같은 소리를 낼 수 있다. 그러나 원본 구간 좌표와 speed 의미가 달라지고 영상 호환은 해결되지 않는다. 따라서 그 방법을 호환 대책으로 채택하지 않는다. 권고안은 구버전 재저장 미지원과 원본 프로젝트 사본 보관이다. 구버전은 새 경고 필드도 모르므로 새 필드만으로 구버전 열기를 차단할 수 없다.

## 결정
결정 번호는 spec 승인 뒤 예약한다.

- **D1 클립별 선택 배속:** 배속의 정본은 선택 필드 `speed`다. 원본 구간과 타임라인 구간을 분리한다. 기본값은 1이며 Q1·Q2의 권고 범위를 전제로 한다.
- **D2 렌더 공통 경로:** 영상은 Remotion playbackRate로 처리한다. 새 ffmpeg setpts 영상 렌더 경로는 추가하지 않는다. 원본 소리와 stems는 영상의 배속을 따른다. [0016](../../decisions/0016-caption-layers-opacity-brand.md)을 보완한다.
- **D3 생성 후 음성 처리:** TTS 모델 속도 지시 대신 생성된 원본을 atempo로 후처리한다. 미리보기와 렌더는 같은 WAV를 쓴다. 음성 배속은 자막·장면 길이를 바꾸지 않으며 [0023](../../decisions/0023-qwen-tts-local.md)을 유지한다.
- **D4 시각 정책:** Q3 권고안은 영상 1의 뒤 영상만 재배치하고 독립 트랙의 시각은 유지하는 것이다. 자동 자막 보정이 필요하면 승인 때 이 항목을 바꿔야 한다. 자막 글과 스타일은 [0028](../../decisions/0028-caption-clip-style.md)을 유지한다.
- **D5 비파괴 원본·캐시:** 원본과 후처리 파일은 불변 버전으로 보존한다. 저장·실행 취소·재생성에서 원본 식별자와 배속을 잃지 않는다. 구버전 의미 호환은 Q6 승인 범위로 제한한다.

## 우려 사항
- **C1 자막·장면 동기화 / 소유자: 제품 책임자.** 영상 배속 뒤 자막·수동 배치 클립의 시각은 그대로라 영상 내용과 어긋날 수 있다. 추천: 그대로 둔다. 이유: 앱이 수동 배치의 의도를 판단할 수 없고, 자동 보정은 범위를 가로지르는 클립 규칙을 먼저 정해야 한다.
- **C2 0016 원본 소리·stems와 전환 / 소유자: 편집·렌더 설계 담당자.** 영상만 가속하면 원본 소리가 어긋나므로 배포할 수 없다. 기존 전환의 0.5와 사용자 배속도 별도 처리해야 한다. 이 경로를 같은 변경과 검증에 포함할 것을 권고한다.
- **C3 0023 자막 길이 / 소유자: 제품 책임자.** 음성에 맞춰 자막·장면을 자동으로 늘리거나 줄이는 후보는 현재 결정을 바꾼다. 원본 길이를 바꾸지 않고 후처리·초과 경고로 해결하는 안을 권고한다. 영상 배속으로 자막을 보정하는 정책과 TTS 배속 정책을 혼동하지 않는다.
- **C4 음절 씹힘과 Remotion 버전 / 소유자: 제품 책임자·음성 처리 담당자.** atempo도 청취 품질을 보장하지 않으며 원본에서 누락된 음절을 복원하지 않는다. 4.0.529에서 지원하지 않는 최신 preservePitch를 사용한다고 가정하지 말고, 공통 WAV 후처리와 사용자 청취로 판정할 것을 권고한다.
- **C5 저장 역호환 / 소유자: 제품 책임자.** 0.3.x 는 배속을 모른다. 추천: 새 버전 읽기 호환만 보장한다.
- **C6 저장 공간·원본 세대 / 소유자: 엔진·저장 설계 담당자.** WAV와 실행 취소용 원본 버전이 추가된다. 캐시 키에 원본 내용 버전을 포함하고 프로젝트 단위로 보존할 것을 권고한다. 기존 TTS의 고정 파일 덮어쓰기만 유지하는 방식은 새 실행 취소 요구사항을 충족하지 못한다.

## 검증 기준
1. 저장소 게이트는 `pnpm verify` 하나다. 종료 코드 0과 마지막 `✓ verify passed`가 필요하다. 초안 작성은 기능 구현 완료나 이 게이트 통과를 뜻하지 않는다.
2. Schema 테스트는 배속 없음=1, 허용 범위의 저장·재열기, 범위 밖·0·음수·NaN 거절, 지원하지 않는 클립 배속 거절을 확인한다. 기존 저장 프로젝트 fixture의 길이·자막 스타일·전환 결과를 유지한다.
3. 편집 테스트는 원본 `[2, 6]` 구간을 0.5·1·1.25·2배로 재생할 때의 길이를 확인한다. 2배속 클립의 타임라인 1초 지점에서 나누면 원본 4초에서 나뉘어야 한다. 트림·나누기·트랙 이동 뒤 원본 구간의 합과 시작 시각을 확인한다.
4. 시간 테스트는 영상 1 뒤 클립의 빈틈 없는 재배치, 오버레이 시작 유지와 끝 초과 거절, Q3에 따른 기존 자막·독립 클립 시각 유지, 새 받아 적기 단어 시각의 배속 변환을 확인한다. 반올림으로 0프레임이 되는 편집을 거절한다.
5. 렌더 테스트는 본 영상·겹친 영상·원본 소리·두 stems의 동일 배속과 원본 오프셋을 확인한다. 배속이 다른 양쪽 전환, 양 끝 전환, 전환 길이 축소, 디졸브 볼륨·오디오 핸들을 포함한다. 1배속 전환 회귀 fixture를 유지한다.
6. 음성 후처리 테스트는 0.5·1.25·2배 WAV의 길이 오차가 1/30초 이내인지 검사한다. 440Hz 합성음의 주요 주파수는 1배속 대비 1% 이내여야 한다. WAV 출력 성공·음성 스트림·양의 실제 길이를 확인한다. 이 수치는 제안 기준이며 실제 포장 ffmpeg로 시험한 뒤 plan에서 고정한다.
7. 서버 테스트는 배속만 변경할 때 TTS 호출 0회, 같은 원본에서 다른 배속 생성, 같은 경로의 원본 내용 변경 시 캐시 미사용, 동일 키 중복 작업 방지, 원본 파일 hash 보존, 실패·취소 시 이전 파일·Timeline 보존을 확인한다. TTS·음성 분리·내보내기와 heavy-media 잠금도 확인한다.
8. TTS 테스트는 Q4에 따른 재생성의 배속 유지, 녹음 보존, 실제 재생 길이로 「!」 표시·해제, 자막·장면 길이 불변을 확인한다. 음성을 경고 해제 목적으로 자르지 않았는지 확인한다.
9. UI 테스트는 PropertyRow 한 줄의 배속 값, 키보드 확정·취소, 잘못된 값, 처리 중 상태·취소, 단일 변경의 실행 취소·다시 실행, 저장·재열기를 확인한다. 처리 도중 선택·원본·배속이 바뀐 오래된 응답은 적용하지 않는다.
10. 미디어 통합 테스트는 미리보기 props와 MP4가 같은 Timeline·후처리 파일을 사용하고 길이가 1프레임 이내로 일치하는지 확인한다. 0.5·1·2배 영상의 시작·끝 프레임과 원본 소리 동기를 검사한다. 단일 Remotion prop mock만으로 이 검증을 대체하지 않는다.
11. 배포 전에는 Tauri WebKit 미리보기와 MP4를 Q5의 한국어 문장으로 비교 청취한다. 사람이 승인한 문장·배속·판정을 검증 기록에 남긴다. 자동 피치·길이 시험 통과만으로 음절 씹힘 감소를 보고하지 않는다.
12. 0.3.1 schema로 새 fixture를 읽고 다시 저장하는 테스트는 배속 손실을 확인한다. 이는 알려진 미지원 동작을 문서화하는 시험이다. 구버전 의미 호환을 통과했다고 보고하지 않는다.

공식 API 근거: [Remotion Audio](https://www.remotion.dev/docs/media/audio)의 preservePitch는 4.0.538부터다. [FFmpeg atempo](https://ffmpeg.org/ffmpeg-filters.html#atempo)는 2 초과에서 일부 sample을 건너뛴다고 명시한다. [FFmpeg atrim](https://ffmpeg.org/ffmpeg-filters.html#atrim)은 timestamp를 바꾸지 않으므로 asetpts를 뒤에 둔다. [FFmpeg setpts/asetpts](https://ffmpeg.org/ffmpeg-filters.html#setpts_002c-asetpts)는 PTS 변경과 0.5×PTS 가속 예시를 제시한다. 이 문서 확인은 현재 앱 번들의 필터 실행 검증을 대신하지 않는다.
