# Intent: playback-speed
Author: sumin.p. Status: accepted.

## 문제
사용자는 “영상과 음성의 배속을 지정하는걸 추가하고싶어”라고 요청했다. 현재 스튜디오는 영상과 음성을 1배속으로 편집하므로, 생성한 음성의 말하는 속도를 나중에 바꾸지 못한다. 사용자는 “음성의 경우 생성하고 나서 배속을 설정하면 음절 씹힘현상등이 줄어들테니까 후처리가 필요하겠지만 괜찮아”라고 설명했다.

## 기대 결과
- 사용자는 영상 클립과 생성이 끝난 음성 클립을 선택하고 배속을 지정한다. 선택한 값은 Inspector에 표시되고 프로젝트를 다시 열어도 유지된다.
- 미리보기와 내보낸 MP4는 같은 배속과 구간을 사용한다. 원본 구간을 유지한 채 2배속을 적용하면 그 구간의 재생 길이는 1배속의 절반이 된다.
- 음성 배속 변경은 이미 만든 음성을 후처리한다. 배속만 바꿀 때 TTS 모델을 다시 실행하지 않는다. 사용자는 바꾼 음성을 미리보기에서 듣고 1배속으로 되돌린다.
- 음성 후처리는 피치를 유지한다. 음절 씹힘 감소는 사용자의 기대이며, 현재 확인한 효과는 아니다. 같은 문장을 배속별로 듣는 판정 방법은 Q5에서 정한다.
- 사용자는 실행 취소 한 번으로 배속 변경 전의 클립과 길이를 복원한다. 자막보다 긴 TTS 음성의 「!」 경고는 후처리한 재생 길이에 맞춰 바뀐다.
- 프로젝트 전체의 미리보기 재생 속도, TTS 모델의 말하기 속도 지시, 음성 내용 복원, 역재생, 구간별 가변 배속은 이번 변경의 대상이 아니다. 짤·효과음의 포함 여부는 Q1에서 정한다.

## 영향 범위
- 사용자: 스튜디오에서 영상과 음성을 편집하는 사용자다. 배속 설정은 선택 클립의 속성이 된다.
- 편집: 영상 1의 빈틈 없는 연결, 영상 2 이상의 독립 시작 시각, 원본 소리와 분리한 목소리·배경의 동기화에 영향을 준다.
- 자막: 기존 자막의 시각, 받아 적은 단어의 원본 시각 변환, 자막 단위 TTS 길이 경고에 영향을 준다.
- 시스템: 클립 저장 형식, 길이 계산, 자르기·트림, 실행 취소, Remotion 미리보기·MP4 렌더, ffmpeg 음성 후처리와 캐시가 바뀐다.
- 외부 연동: 새 AI 제공자나 유료 API는 추가하지 않는다. 로컬 Qwen3-TTS·ffmpeg·Remotion을 사용한다.

## 제약
- 영상 1은 빈틈 없이 이어진다. 원본 소리와 분리한 목소리·배경은 해당 영상의 배속을 따른다. 미리보기와 렌더는 같은 Timeline 변환을 사용한다([0016](../../decisions/0016-caption-layers-opacity-brand.md)).
- TTS는 첫 자막 레이어의 메인 자막 단위로 생성한다. 음성 배속만 바꿀 때 자막 클립과 장면 길이를 자동 변경하지 않는다. TTS·내보내기·음성 분리의 동시 실행 금지는 유지한다([0023](../../decisions/0023-qwen-tts-local.md)).
- 자막의 글·강조 표기·스타일 재정의는 유지한다([0028](../../decisions/0028-caption-clip-style.md)). 영상 배속 변경에 따른 자막 시각 정책은 Q3에서 별도로 정한다.
- 음성 후처리는 원본 파일을 덮어쓰지 않는다. 다른 배속으로 바꿀 때 직전 후처리 파일에 배속을 누적하지 않는다. 실패·취소 시 이전 클립을 유지한다.
- 배속 필드가 없는 프로젝트는 1배속으로 읽는다. 새 프로젝트를 0.3.x에서 열고 다시 저장할 때의 의미 보존은 아직 보장하지 않는다(Q6).
- 배속 범위와 청취 품질 기준은 아직 승인되지 않았다. “음절 씹힘 감소”를 자동으로 보장한다고 표시하지 않는다.

## 열린 질문
- **Q1 대상:** 영상은 영상 1과 영상 2 이상의 원본 영상으로, 음성은 TTS·녹음·불러온 음성으로 한정할 것인가? 추천은 이 범위다. 사진은 재생 속도가 없고, 짤의 반복과 효과음은 별도 동작을 정해야 한다.
- **Q2 범위:** 배속 범위와 입력 간격은 얼마인가? 추천은 0.5–2.0배, 0.05 간격, 기본 1.0배다. 감속과 가속을 제공하면서 ffmpeg atempo의 2 초과 sample skip 경로를 피한다.
- **Q3 시각:** 영상 1 배속으로 길이가 바뀔 때 기존 자막·겹친 영상·음성·효과음의 시각도 자동으로 바꿀 것인가? 첫 버전은 이 시각을 유지하고 동기화 확인 안내를 표시하는 안을 추천한다. 현재 장면 연결만으로 손으로 배치한 모든 클립의 의도를 판단할 수 없다.
- **Q4 재생성:** 배속을 설정한 TTS를 「다시 만들기」로 생성하면 배속을 유지할 것인가? 추천은 배속 유지다. 새 원본에 후처리를 다시 적용하면 사용자의 속도 설정을 지키면서 누적 변환을 피한다.
- **Q5 청취 판정:** “음절 씹힘현상등이 줄어들”었는지는 어떤 문장과 배속에서 판단할 것인가? 추천은 사용자가 고른 한국어 문장을 같은 1배속 원본에서 1.0·1.25·1.5·2.0배로 만들어 비교하는 방식이다. 길이·피치 검사만으로 음절 보존을 판정할 수 없다.
- **Q6 구버전:** 새 배속 프로젝트를 0.3.x에서도 같은 속도로 편집해야 하는가? 추천은 기존 프로젝트를 새 버전에서 읽는 호환만 보장하는 것이다. 0.3.x는 배속 필드를 모르며, 재저장하면 배속 정보가 사라질 수 있다. 구버전으로 열기 전에는 프로젝트 사본을 보관한다.
