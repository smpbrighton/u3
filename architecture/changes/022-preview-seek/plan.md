# W22 미리보기 재생 헤드 복구 계획

Track: lite.

## 검토 목록
- 없음. 기대 동작, 실패 테스트 선행, 앱 재현 절차, 커밋 규칙을 지정했다.

## 결정
- 재생 시각을 프레임으로 바꾸는 순수 함수와 Player 준비 뒤 seek 대상 프레임을 정하는 순수 함수를 둔다.
- Player가 처음 준비될 때 올바른 `initialFrame`으로 시작하고, 준비 완료 뒤 seek effect도 실행한다.
- 이미 받은 소스로 편집을 렌더링하는 동안 Player를 유지한다. 새 소스를 받는 동안 기존 source map과 준비 상태를 유지해 준비 안내가 다시 나타나지 않게 한다.
- 재생 중 편집 때 재생 상태 변경을 추가하지 않는다.
- 새 타임라인의 마지막 유효 프레임을 넘는 재생 헤드는 마지막 프레임 시각으로 자르고, Studio 상태와 미리보기를 같은 값으로 맞춘다.
- 실패 테스트만 먼저 커밋한다. 구현 커밋에서는 `tests/`를 수정하지 않는다.

## 순서
1. 이 계획을 `W22: 미리보기 재생 헤드 계획`으로 먼저 커밋한다.
2. 시간→프레임 변환, 프레임 범위 자르기, Player 준비 뒤 seek 대상 결정을 검증하는 실패 테스트를 작성하고 `W22: 미리보기 재생 헤드 실패 테스트`로 커밋한다.
3. 테스트 파일을 바꾸지 않고 순수 함수를 구현한다. `Preview`는 올바른 `initialFrame`으로 마운트하고 준비 완료 때 seek한다. 편집 중 source fetch는 Player를 내리거나 준비 문구를 다시 보이지 않게 한다.
4. `Studio`의 재생 헤드 상태를 새 render의 마지막 유효 프레임으로 맞춘다. 재생 중 편집의 기존 동작을 유지한다.
5. `pnpm verify`를 실행하고 마지막 20줄을 보존한다. diff와 커밋을 확인한다.
6. 지정된 데이터·라이브러리 경로로 `pnpm tauri dev`를 실행하고 앱에서 재현 절차를 시도한다. 앱 창만 `out/manual/w22-preview.png`에 캡처한다. 자막과 프레임을 확인한다.
7. 실행한 Tauri 앱과 sidecar, `target/debug/u3`를 종료한다. 모든 변경을 커밋하고 push하지 않는다.

## 위험과 대응
- `initialFrame`은 Player 생성 시 초기 프레임을 정하고 duration 범위를 검증한다. source map 갱신은 같은 Player를 유지하며, 실제 재마운트 경로는 준비 완료 의존성의 seek effect로 보완한다.
- 미디어 소스 갱신 중에는 오래된 map을 유지한다. 새 편집 미디어가 map에 없는 순간에는 해당 프레임의 미디어가 늦게 나타날 수 있지만, 편집마다 로딩 안내가 깜박이지 않게 한다.
- 재생 중 편집은 현재 playing prop과 재생 상태 effect를 유지하고, GUI 확인 결과를 보고한다.
- GUI 드래그를 자동화할 수 없으면 제한 사항을 적는다. 개발 실행의 WebKit 미디어 오류로 영상이 검으면 자막 표시를 판정 기준으로 쓴다.
- 새 devDependency를 추가하지 않는다.

## 완료 증거
- 실패 테스트 커밋 뒤 테스트 파일을 수정하지 않은 구현 커밋.
- `pnpm verify` 종료 코드 0, 마지막 줄 `✓ verify passed`.
- 지정 실행 경로에서 편집 후 재생 헤드 위치 또는 마지막 프레임이 맞는 앱 창 캡처. 자동 조작을 못 했거나 미디어 오류가 있으면 결과를 보고한다.
- 실행한 프로세스 종료 결과.

## 롤백
- W22 커밋을 역순으로 되돌린다. 데이터 스키마는 바꾸지 않는다.
