## 열린 질문에 대한 답
1. 원본 장면 배경을 남긴다. 장마다 「AI 이미지 / 원본 장면」을 고른다. 이유: AI 가 상품을 다르게 그리거나 가격표처럼 실제 글자가 중요할 때 되돌릴 길이 필요하다.
2. 새 영상 캐러셀의 기본값은 AI 이미지다. 이미 만든 캐러셀은 원본 장면으로 남는다(저장 값에 모드가 없으면 원본 장면).
3. 지시문에 「참고 사진의 상품을 같은 상품으로 그린다(종류·색·모양·패키지 형태). 새 글자·숫자·로고·워터마크를 만들지 않는다」를 넣는다. 상품 패키지의 라벨 글자는 재현을 보장하지 않는다. 라벨이 중요하면 원본 장면을 고른다.
4. 강조(상자·AI 윤곽)는 그 장에 보이는 배경 이미지를 기준으로 적용한다. AI 이미지 모드면 생성 이미지에서 Jev Box 로 상자를 찾고, AI 윤곽도 생성 이미지를 참고로 만든다. 배경을 다시 만들면 자동 상자를 다시 찾는다(사용자가 그린 상자는 지운다).
5. 기획 단계에서 장마다 `imagePrompt` 를 만든다. 검토 화면에서 「주제로」 캐러셀과 같은 지시문 입력란으로 고친다.
6. 영상 캐러셀 기획 프롬프트를 고친다. 2번(프레임 미제공)은 유지하고, 8번의 「새 배경 이미지 제작 지시문을 추가하지 않는다」를 지우고, 「imagePrompt 에는 선택한 장면의 상품·대상을 중심에 둔 구도·분위기·조명과 글 여백을 쓰되, 보지 않은 화면의 색·모양을 단정하지 않는다」 규칙을 더한다. 기본 프롬프트 revision 을 올리고 원격에 공개한다(0035).

## 요구사항
1. 새 「영상으로」 캐러셀에서 이미지 만들기를 누르면 장마다 고른 장면 프레임을 참고 이미지로 붙인 image_gen 이 돌고, 결과가 그 장의 배경이 된다.
2. 장마다 배경 모드를 「AI 이미지」「원본 장면」 중에서 바꿀 수 있다. 원본 장면으로 바꾸면 이미 뽑은 프레임을 바로 쓴다(재생성 없음). AI 이미지로 바꾸면 생성 이미지가 있으면 그것을, 없으면 생성을 시작한다.
3. 시각을 바꾸고 「이 시각으로 다시 만들기」를 누르면 프레임을 다시 뽑고, AI 이미지 모드면 그 프레임으로 다시 생성한다.
4. AI 이미지 모드에서 「다시 만들기」는 같은 프레임·지시문으로 새 이미지를 만든다. 이전 이미지는 버전으로 남는다(기존 `saveImageVersion` 규칙).
5. 기획 결과 장마다 `imagePrompt` 가 있고 검토 화면에서 고칠 수 있다. 비어 있으면 AI 이미지 생성은 「지시문 없음」으로 실패한다(「주제로」와 같음).
6. 생성 실패는 그 장만 실패로 표시하고, 원본 장면으로 바꿀 수 있다.
7. 강조는 그 장에 보이는 배경 이미지 기준으로 동작한다.
8. 받기(PNG)는 그 장에 보이는 배경으로 합성한다.
9. 이미 저장된 영상 캐러셀은 열었을 때 원본 장면 모드로 보이고 동작이 바뀌지 않는다.

## 설계
- 데이터(`src/core/carousel.ts`): frame 배경에 `mode: "ai" | "frame"`(기본 `"frame"`, 새 기획은 `"ai"`), `image?: CarouselImage`(생성 이미지 최신 버전), `imageStatus`·`imageError`(생성 상태, 프레임 상태와 분리). 합성·표시용 함수 `carouselSlideImage` 는 모드에 따라 `image` 또는 `frame`(AI 윤곽이면 그 이미지)을 고른다.
- 기획(`src/engine/routes/carousels.ts`): `DerivedPlanSchema` 에 `imagePrompt` 추가, 새 슬라이드는 `mode: "ai"`. 기획 프롬프트(`src/core/carousel-prompt.ts` 의 영상 본문)를 답 6 대로 고치고 `PROMPT_REVISION` 을 올린다.
- 생성(`POST /api/carousels/:id/generate`, project 분기): 프레임을 뽑고(기존 `extractSlideFrame`), 모드가 `"ai"` 면 이어서 `runCarouselImage` 를 `referenceImage = 프레임` 과 새 지시문 빌더로 부른다. 지시문 빌더는 `codex-image.ts` 에 `referencePrompt({ imagePrompt, style, aspect, ... })` 로 두고, 답 3 의 문장을 넣는다(지금의 `outlinePrompt` 는 AI 윤곽 전용으로 둔다).
- 장면 다시 뽑기(`POST …/frame`): 프레임을 다시 뽑은 뒤 모드가 `"ai"` 면 생성 작업을 큐에 넣고 202 로 작업을 돌려준다. 원본 장면 모드는 지금처럼 동기 응답.
- 모드 바꾸기: `PUT /api/carousels/:id/slides/:slideId` 의 background 에 `mode` 를 받는다. `"ai"` 로 바꾸는데 `image` 가 없으면 생성을 시작한다.
- 강조: `highlight` 라우트의 Jev Box·AI 윤곽 입력 이미지를 `carouselSlideImage` 기준 배경으로 바꾼다. 배경을 다시 만들면 `clearAutomaticHighlight` 를 부른다.
- 화면(`src/ui/screens/carousel/BackgroundSection.tsx`·`CarouselReview.tsx`): 배경 절에 모드 선택(「AI 이미지」「원본 장면」), AI 모드일 때 「다시 만들기」와 생성 상태, 버튼 이름 「이 시각으로 다시 만들기」(AI)·「이 시각으로 다시 뽑기」(원본). 검토 화면의 영상 캐러셀 장에 이미지 지시문 입력란.

## 결정
- 0026 을 0036 으로 대체한다: 영상 파생 캐러셀의 배경은 고른 장면을 참고 이미지로 image_gen 이 만든 그림이 기본이고, 장마다 원본 장면으로 바꿀 수 있다. → `../../decisions/0036-scope-carousel-video-genimage.md`

## 우려 사항
1. **글자 없는 배경 규칙(0027)과 상품 패키지 글자.** image_gen 은 패키지 글자를 바꾸거나 깨뜨릴 수 있다. 정책 소유자: 제품 책임자(사용자). 추천: 라벨 재현을 보장하지 않고 원본 장면 전환으로 보완한다.
2. **사용량·시간 증가.** 영상 캐러셀 5장이면 image_gen 5회(장당 수십 초, ChatGPT 사용량 소모)가 는다. 정책 소유자: 사용자. 추천: 그대로 받아들이고 동시 수 설정(0027)으로 조절한다.
3. **원격 기본 프롬프트 revision.** 영상 기획 프롬프트를 바꾸면 0.3.7·1.0.0 설치본도 원격으로 새 본문을 받는다. 그 앱들은 `imagePrompt` 를 영상 캐러셀에서 쓰지 않으므로 지시문이 생겨도 무시된다(DerivedPlanSchema 가 모르는 키를 버림). 정책 소유자: 개발. 추천: 이 변경의 앱 릴리스와 같은 날 공개한다.
4. **사람 얼굴.** 참고 프레임에 사람 손·얼굴이 있으면 image_gen 이 다른 사람처럼 그린다. 0026 은 「인물 사진」을 범위 밖에 둔다. 정책 소유자: 사용자. 추천: 지시문에 「사람은 손 정도만, 얼굴은 그리지 않는다」를 넣는다.

## 검증 기준
- `pnpm verify` 가 `✓ verify passed` 로 끝난다.
- 서버 시험: 영상 캐러셀 생성이 프레임 추출 뒤 참고 이미지를 붙여 이미지 생성 서비스를 부른다(가짜 서비스로 인자 확인). 원본 장면 모드는 생성 서비스를 부르지 않는다. 모드 없는 저장본은 원본 장면으로 읽힌다. 시각 다시 뽑기가 AI 모드에서 생성 작업을 시작한다. 받기가 모드에 맞는 배경을 쓴다.
- 지시문 빌더 시험: 참고 이미지 경로, 「같은 상품」, 「새 글자 없음」, 얼굴 금지 문장이 들어간다.
- UI 시험: 모드 전환, 「다시 만들기」, 검토 화면 지시문 입력.
- 실기(사용자): 영상 캐러셀을 새로 만들어 상품 장면이 같은 상품으로 그려지는지 확인한다.
