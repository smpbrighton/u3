# W28 SEED 칩과 라벨 결함 수정 계획

Track: lite.

## 검토 목록
- W26·W27 계획, SEED 화면 점검 기록, 전체 UI 코드와 지정된 화면설계를 대조한다.
- SEED 공통 문서와 React 구현 문서를 공식 인덱스의 링크로 확인한다.
- CSS/DOM 레이아웃 결함은 vitest/jsdom에서 실패 검증을 만들 수 없다. 레이아웃 수정 커밋은 테스트 없이 넣고 본문에 이유를 기록한다.

## 결정
- 단계 이동에는 SEED `Chip Tabs`를 사용한다. 문서는 카테고리나 필터를 선택해 콘텐츠를 전환하는 용도와 선택 상태를 설명한다. 이 흐름은 단계 선택으로 입력·대본·스튜디오 화면을 전환한다.
- 두 단계 화면은 동일한 Chip Tabs 스니펫을 사용한다. React 문서에는 `medium`, `large`가 있고 `small`은 없다. 헤더에 맞는 가장 작은 문서 size인 `medium`을 사용한다. 갈 수 없는 단계는 disabled 상태로 둔다.
- 설정의 Select 자체 label만 유지해 라벨 중복을 없앤다.
- SEED 내부 클래스는 덮지 않는다. 레이아웃은 부모의 flex/grid와 gap으로 조정한다.
- Script.tsx에서는 헤더 마크업만 바꾸고, 대본 생성 흐름과 W29 대상 파일은 수정하지 않는다.
- 요청된 UI 범위에서 같은 종류의 크기·라벨·정렬·겹침 결함을 찾아 고친다. 기능, 단축키, 포인터 끌기 동작은 유지한다.
- CSS/DOM 결함만 수정하므로 테스트 파일은 바꾸지 않는다. 테스트가 기존 마크업에 의존해 실패하면 해당 테스트만 별도 선행 커밋한다.
- 캡처는 지정한 시험 데이터와 라이브러리를 사용한다. 프로젝트 데이터 원본은 보존한다.
- 모든 변경은 이 브랜치에 커밋한다. push, main, Jira, 위키는 건드리지 않는다.

## 바꿀 파일
- `src/ui/**` (Script.tsx는 헤더 마크업만)
- `seed-design/ui/` (CLI 신규 스니펫만), SEED 스니펫 의존성에 한해 `package.json`·`pnpm-lock.yaml`
- `docs/ui-design-check.md`
- 이 계획 파일

## 순서
1. 이 계획을 `W28: SEED 칩과 라벨 수정 계획`으로 첫 커밋한다.
2. SEED 공통·React 인덱스의 문서, 컴포넌트 계약, CLI 도움말을 확인하고 필요한 스니펫을 설치한다.
3. Input·Script 단계 표시와 Settings Select 라벨을 고치고 화면 단위로 커밋한다.
4. 홈, 입력, 대본, 설정, Studio, Dialog, Snackbar 전체에서 같은 결함을 점검하고 수정한다. 화면 단위 커밋을 만든다.
5. `docs/ui-design-check.md`에 수정 내용과 캡처·미확인 상태를 기록한다.
6. 지정 환경으로 `pnpm tauri dev`를 실행하고 가능한 화면을 창 단위로 `out/manual/w28-<화면>.png`에 캡처한다. 실행한 프로세스를 종료한다.
7. `pnpm dlx @seed-design/cli@latest compat`와 `pnpm verify`를 실행한다. 종료 코드와 verify 마지막 20줄을 기록한다.
8. 모든 변경을 이 브랜치에 커밋한다. push하지 않는다.

## 완료 증거
- 단계 칩 중복 스타일과 설정 라벨 중복을 수정한다.
- 전체 점검에서 확인한 동일 유형 결함과 수정 이유를 결함 번호로 기록한다.
- 캡처 상태, compat 결과, verify 종료 코드 0과 마지막 줄 `✓ verify passed`를 보고한다.

## 롤백
- W28 수정 커밋을 역순으로 되돌린다. 시험 데이터 원본은 변경하지 않는다.
