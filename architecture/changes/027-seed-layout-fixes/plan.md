# W27 SEED 화면 레이아웃 결함 수정 계획

Track: lite.

## 검토 목록
- W26 패키징 앱의 창 캡처와 W25 이전 화면을 비교한다.
- 변경 범위와 완료 조건이 지정되어 있어 lite로 진행한다.
- CSS 레이아웃 수정은 vitest/jsdom으로 실패 검증을 만들 수 없다. 레이아웃 수정 커밋은 테스트 파일을 바꾸지 않고, 커밋 본문에 이유를 기록한다.

## 결정
- SEED 컴포넌트 내부 클래스를 `!important`로 덮지 않는다.
- 바깥 flex/grid, `min-width`, 크기 prop, SEED size prop과 토큰으로 배치를 수정한다.
- 화면 동작과 단축키를 유지한다.
- 원본 시험 프로젝트는 읽기 전용으로 두고, 워크트리의 `out/manual/store/projects/`로 복사해 실행한다.
- 수정은 이 워크트리 브랜치에 커밋하고 push, main, Jira, 위키는 건드리지 않는다.

## 바꿀 파일
- `src/ui/**`
- `seed-design/`의 스니펫 설정만
- `docs/ui-design-check.md`
- 이 계획 파일

## 순서
1. 계획을 `W27: SEED 레이아웃 수정 계획`으로 첫 커밋한다.
2. SEED 문서 인덱스의 링크만 따라 관련 API 계약을 확인하고, W26 코드와 모든 지정 화면설계를 대조한다.
3. 홈 사이드바와 프로젝트 카드, Studio 미디어 목록과 짤 격자, 타임라인 확대 도구와 트랙 음소거 버튼의 레이아웃을 고친다.
4. 입력·대본·설정·Inspector·Dialog·Menu·Snackbar 화면을 코드와 개발 앱으로 점검하고 같은 종류의 결함을 고친다.
5. `docs/ui-design-check.md`에 수정 내용과 캡처·미확인 상태를 기록한다.
6. 지정된 프로젝트 데이터를 복사하고 지정 환경으로 `pnpm tauri dev`를 실행한다. 조작 가능한 화면을 앱 창 단위로 `out/manual/w27-<화면>.png`에 캡처한 뒤 실행한 앱과 sidecar를 종료한다.
7. `pnpm verify`를 실행한다. 종료 코드 0과 마지막 줄 `✓ verify passed`를 확인한다.
8. 모든 변경을 이 브랜치에 한국어 커밋으로 남기고 push하지 않는다.

## 완료 증거
- 일곱 레이아웃 결함과 전체 점검에서 발견한 같은 유형의 결함을 수정한다.
- 고친 화면과 확인하지 못한 화면을 문서와 마지막 보고에 명시한다.
- `pnpm verify` 종료 코드 0, 마지막 줄 `✓ verify passed`를 확인한다.
- 모든 변경을 커밋한다.

## 롤백
- W27 수정 커밋을 역순으로 되돌린다. 시험 데이터 원본은 변경하지 않는다.
