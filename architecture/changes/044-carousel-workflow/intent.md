## 문제
캐러셀 제작의 시작점이 둘로 갈라져 있고, 글은 AI 가 정한 대로 지나가며, 글의 배치·효과를 고칠 수 없다.

사용자 발의: "캐러셀은 두가지 제작 방법이 있어. 그냥 캐러셀을 만드는것과 영상으로부터 캐러셀을 만드는법. 그런데 이 두 선택사항으로 시작점이 모호한것", "기존에 uuu 에서 스티븐이 작업했던 내역으로 캐러셀을 보면 사진과 텍스트를 분리해서 생성되게끔 한거 같은데 … 캐러셀에서 텍스트가 별도로 생성될거라면 텍스트의 자유롭게 배치하는 위치라던가 텍스트의 효과가 지금으로썬 부족한 편", "기존 스티븐의 캐러셀생성방식을 채용하고 절차는 최대한 간단하게", "지금은 너무 간소화되어서 각 이미지가 어떤 내용이 담길지 AI한테 맡기면 너무 아무것도 없이 지나가버려 … 각 생성 이전에 타이틀이나 대본등을 먼저 작성하고 사람이 검토하고 이미지 생성으로 넘어가는게 좋을것 같아".

지금 코드에서 확인한 것:
- 캐러셀 목록의 「새 캐러셀」은 주제 방식만 연다. 영상 파생은 영상 목록 카드 메뉴와 스튜디오 머리줄의 「캐러셀 만들기」에만 있다.
- 「만들기」가 기획(codex)과 이미지 생성을 한 호출에서 연달아 시작한다(`src/ui/screens/Carousels.tsx:72-74`). 사람이 글을 보는 단계가 없다.
- 글은 배경과 분리돼 있다(결정 0019). 그러나 장마다 제목·본문 두 글과 위치 「위·가운데·아래」뿐이고 크기 76/40px·흰색·그림자는 고정이다(`src/remotion/CarouselSlide.tsx`). uUu 는 글 객체마다 위치·폭·폰트·굵기·크기·색·정렬을 가지고 로고와 배경 밝기·음영도 있다(`uUu/src/core/carousel.ts` `CarouselText`·`CarouselSlideEditable`).
- 화풍(`style`)은 AI 가 정하고 화면에 입력이 없다.
- 글이 장 밖으로 넘쳐도 알리지 않는다.

## 기대 결과
- 「새 캐러셀」 한 곳에서 「주제로」와 「영상으로」를 고른다. 영상 목록·스튜디오의 「캐러셀 만들기」는 같은 대화상자를 프로젝트가 골라진 상태로 연다.
- 흐름은 두 방식 모두 같다: 요청 → AI 기획 → **검토**(장마다 제목·본문·이미지 지시문을 고치고, 장을 더하고 지우고 순서를 바꾼다) → 「이미지 만들기」 → 편집 → 받기. 검토를 거치지 않고 이미지가 만들어지지 않는다.
- 장의 글은 객체다. 제목·본문은 기본이고 글을 더할 수 있다. 객체마다 미리보기에서 끌어 옮기고 폭을 바꾸며, 폰트(자막과 같은 세 가지)·굵기·크기·색·정렬·효과(없음·그림자·반투명 바·외곽선)를 고른다.
- 로고(설정의 워터마크 이미지)를 장에 켜고 위치·크기를 정한다. 배경 밝기·음영을 조절한다.
- 글이 장 밖으로 넘치면 미리보기와 장 목록에 표시하고, 받기 전에 확인한다.
- 미리보기와 받은 PNG 는 같은 Remotion 컴포넌트로 합성해 같은 모양이다(0019 유지).
- 판정 기준: (1) 새 캐러셀 대화상자 테스트가 두 방식 모두 검토 단계로 보낸다. (2) 검토에서 고친 글이 이미지 지시문과 편집 화면에 반영된다. (3) 글 객체를 끌어 옮긴 좌표가 저장되고 PNG 에 같은 위치로 그려진다(렌더 테스트). (4) 043 아티팩트에 새 캐러셀 보드가 추가되고 pages.md 6 절이 이 흐름으로 바뀐다.
- 범위 밖: uUu 의 근거 조사, 기획안 여러 개 비교, 톤 프리셋, 실존 인물 사진, 마스크 편집, 움직이는 장.

## 영향 범위
- 사용자: 캐러셀 목록·새 캐러셀·검토·편집 화면, 영상 목록 카드 메뉴, 스튜디오 머리줄.
- 시스템: `src/core/carousel.ts`(장 스키마·마이그레이션), `src/engine/routes/carousels.ts`·`src/engine/carousel-store.ts`(단계·장 편집 API), `src/remotion/CarouselSlide.tsx`·`carousel-layout.ts`(글 객체·로고·밝기 합성), `src/engine/pipeline/carousel-frame.ts`(PNG), `src/ui/screens/Carousels.tsx`·`carousel/*`, `tests/`.
- 결정: 0022(범위)와 0019(캐러셀 이미지·글 얹기)를 대체한다.
- 043: pages.md 6 절과 아티팩트 캐러셀 페이지를 바꾼다. 043 단계 B 의 B3 묶음은 이 변경의 plan 으로 대체한다.
- 외부 연동: 없음. codex image_gen 과 Jev 는 그대로.

## 제약
- 043 디자인 체계(shadcn 부품, 토큰, 화면 글 규칙: 설명문·도움말 없음)를 따른다. 화면은 043 아티팩트에 보드로 들어간다.
- AI 는 codex(기획·이미지)와 Jev(강조 상자)만 쓴다(0024). 이미지는 글자 없는 배경으로 만든다(0019).
- 저장된 캐러셀(제목·본문·`textPlacement`)은 읽을 때 글 객체로 바꾸고 모양을 유지한다.
- 미리보기와 PNG 는 같은 컴포넌트로 합성한다. 글 줄바꿈이 둘에서 같아야 한다.
- 절차는 단계가 늘어도 화면 수는 최소로 한다. 검토는 한 화면이다.

## 열린 질문
1. 영상 목록 카드 메뉴·스튜디오 머리줄의 「캐러셀 만들기」를 남기는가.
2. 글 객체는 제목·본문 고정에 추가 글을 몇 개까지 허용하는가.
3. 글 효과는 없음·그림자·반투명 바·외곽선 넷으로 충분한가.
4. 로고는 설정의 워터마크 이미지를 쓰는가, 캐러셀에서 따로 고르는가.
5. 게시 캡션(SNS 본문 글)을 기획에서 함께 만들고 받기 때 `caption.txt` 로 내는가.
6. 영상 파생 캐러셀의 검토 화면에서 장면(시각)도 바꾸는가, 편집 화면에서만 바꾸는가.
7. 화풍 입력을 요청 대화상자에 두는가, 검토 화면에 두는가.
8. 넘친 글이 있을 때 받기를 막는가, 확인 뒤 받게 하는가.
