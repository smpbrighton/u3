## 열린 질문에 대한 답
1. 판정 기준: 후보 1(30초 대본 음성을 60초 안에)과 후보 2(사용자 청취 판정)를 함께 쓴다. 후보 3(whisper 일치율)은 보조 지표로 스파이크에서만 잰다. 속도는 기계로 재고 품질은 사람만 판정할 수 있기 때문이다.
2. 대본 장면 단위로 만든다. 장면 caption 이 한 번에 읽히는 단위이고 장면 시각(`startSec`)이 이미 타임라인에 있다. 자막 클립 단위는 문장 중간에서 억양이 끊긴다.
3. 장면을 늘리지 않는다. 음성이 장면보다 길면 음성을 그대로 두고 그 장면에 경고를 보인다. 장면 길이는 원본 영상 구간에 묶여 있어 늘릴 수 없는 경우가 있다.
4. 기본 화자는 Sohee 다. 설정에서 9개 프리셋 화자 중 하나를 고를 수 있다. 말투 지시(instruct)는 1.7B 모델에서만 동작하므로 설정에 한 줄 입력으로 둔다.
5. 넣지 않는다. 목소리 복제는 동의 확인 같은 별도 정책이 필요하다. 다음 단계로 넘김.
6. Swift 도우미를 기본안으로 한다. 앱에 Python 런타임을 넣지 않는 결정(0007·0008)을 지킨다. 스파이크 S1 에서 Swift 도우미가 1.7B CustomVoice 를 읽지 못하면 이 답을 다시 연다(우려 사항 1).
7. 1.7B CustomVoice 를 기본으로 한다. 한국어 프리셋 화자 WER 이 0.6B(3.053)보다 낮다(1.741). 스파이크 S1 에서 속도 기준을 못 넘으면 0.6B 로 내린다.

## 요구사항
1. 사용자는 설정의 모델 항목에서 TTS 모델 받기를 누른다. 앱은 받기 진행률을 보이고, 받은 뒤 모델 상태를 "준비됨"으로 보인다.
2. 모델이 없으면 "음성 만들기" 버튼은 모델 받기 안내를 보인다.
3. 사용자는 대본 화면에서 "음성 만들기"를 누른다. 앱은 장면마다 caption 으로 음성 파일 하나를 만든다.
4. 앱은 만든 음성을 목소리 트랙에 장면 시작 시각으로 놓는다. 클립 하나가 장면 하나다.
5. 앱은 TTS 에 넘기기 전에 caption 에서 이모지와 줄바꿈을 지운다.
6. 음성 길이가 장면 길이보다 길면 앱은 그 장면에 경고를 보인다.
7. 사용자는 편집 화면에서 장면 음성 하나를 다시 만든다. 다시 만든 음성은 같은 클립 자리를 바꾼다.
8. 사용자는 생성을 취소한다. 취소하면 만들던 파일을 지우고 이미 넣은 클립은 남긴다.
9. 설정에서 화자(기본 Sohee)와 말투 지시 한 줄을 정한다.
10. 생성은 네트워크 없이 동작한다.

## 설계
### 도우미 실행 파일
- `u3-tts`(new): swift-qwen3-tts(MIT)를 감싼 Swift 실행 파일이다. 입력은 표준 입력 JSON(`model`, `speaker`, `instruct`, `items: [{id, text}]`, `outDir`)이다. 출력은 장면마다 `<id>.wav`(24 kHz mono)와 표준 출력 줄 단위 JSON 진행 이벤트다.
- 모델을 한 번 읽고 장면을 차례로 만든다. 장면마다 프로세스를 새로 띄우지 않는다.
- 빌드: `scripts/` 에 Swift 빌드 단계를 더한다. `default.metallib` 를 실행 파일 옆에 둔다. 빌드 캐시는 `U3_BUILD_CACHE` 아래에 둔다.
- 패키징: Tauri `externalBin` 에 `u3-tts` 를 더하고 앱 서명에 포함한다.

### 엔진
- `src/engine/pipeline/models.ts`: `QWEN_TTS_FILES`(Hugging Face 고정 revision, sha256)와 `downloadQwenTts` 를 더한다. 받는 위치는 whisper 모델과 같은 모델 캐시 폴더다.
- `src/engine/pipeline/tts.ts`(new): `u3-tts` 를 띄우고 진행 이벤트를 작업 진행률로 옮긴다. 취소 신호에 프로세스를 끝낸다.
- `src/engine/routes/tts.ts`(new): `POST /api/projects/:id/tts`(장면 목록 → 작업), `POST /api/projects/:id/tts/:sceneId`(장면 하나 다시 만들기). 결과 파일은 프로젝트 `voice/tts-<sceneId>.wav` 다.
- `src/engine/routes/models.ts`: TTS 모델 상태와 받기를 더한다.

### 데이터
- `AudioClip` 스키마는 바꾸지 않는다. TTS 클립은 `voice` 배열에 일반 클립으로 들어간다. 클립 `id` 를 `tts-<sceneIndex>` 로 지어 다시 만들 때 찾는다.
- 설정: `ttsSpeaker`(기본 "Sohee"), `ttsInstruct`(기본 빈 값).

### 화면
- 대본 화면: "음성 만들기" 버튼, 진행률, 장면별 길이 경고.
- 편집 화면 인스펙터: TTS 클립에 "다시 만들기".
- 설정: 모델 항목에 TTS 모델 받기, 대본 항목에 화자 선택과 말투 지시.

### 스파이크 S1(plan 첫 단계)
이 머신(Apple M6, 24GB, macOS 27.0.1)에서 잰다. 결과는 `docs/spikes/qwen-tts.md` 에 둔다.
- `u3-tts` 시험판으로 1.7B CustomVoice(bf16, 8bit)와 0.6B CustomVoice 를 읽는다.
- 30초 분량 한국어 대본 6장면의 생성 시간, 최대 메모리, whisper 일치율을 잰다.
- 사용자가 음성 파일을 듣고 판정한다.

## 결정
- 0022 범위 개정: 0017 을 대체한다. 음성 합성(TTS)을 범위에 넣는다. 나머지 범위는 0017 과 같다. → `../../decisions/0022-scope-add-tts.md`
- 0023 TTS: Qwen3-TTS 1.7B CustomVoice 를 Swift 도우미(swift-qwen3-tts, MLX)로 로컬 실행한다. 모델은 받기를 고를 때 받는다. 기본 화자 Sohee. → `../../decisions/0023-qwen-tts-local.md`

## 우려 사항
1. swift-qwen3-tts 는 1.7B CustomVoice 를 지원 목록에 두지 않았다(0.6B CustomVoice, 1.7B Base, 1.7B VoiceDesign 만 있음). 읽지 못하면 0.6B(한국어 품질 낮음)로 가거나 Python(mlx-audio)을 앱에 넣어야 한다. Python 은 0007·0008 의 전제를 깬다. 정책 소유자: 제품 책임자. 추천: 스파이크 S1 결과로 정하고, Python 은 넣지 않는다. 이유: 번들 크기와 서명·업데이트 부담이 커진다.
2. 모델 크기 약 4.5 GB(1.7B bf16)를 사용자 디스크에 받는다. 정책 소유자: 제품 책임자. 추천: 8bit 판이 품질 기준을 넘으면 8bit 를 쓴다. 이유: 받기 시간과 디스크가 절반가량 준다.
3. 생성 중 메모리가 codex·Remotion 과 겹치면 24GB 를 넘을 수 있다. 정책 소유자: 엔지니어링. 추천: 내보내기와 TTS 작업을 동시에 돌리지 않게 작업 큐에서 막는다.
4. `default.metallib` 를 앱에 넣고 서명해야 한다. 공증(038-auto-update)과 겹친다. 정책 소유자: 엔지니어링. 추천: 038 병합 뒤 이 변경을 병합한다.
5. AI 가 만든 목소리라는 표시 의무가 플랫폼마다 있다. 정책 소유자: 제품 책임자. 추천: 이번 변경에서는 표시 기능을 넣지 않고, 업로드 단계에서 사용자가 표시한다. 이유: 앱에 업로드 기능이 없다(0017).

## 검증 기준
1. `pnpm verify` 가 종료 코드 0 이고 마지막 줄이 `✓ verify passed` 다.
2. 엔진 테스트: 가짜 `u3-tts`(진행 이벤트와 wav 를 내는 스크립트)로 장면 3개 작업이 목소리 트랙 클립 3개를 장면 시작 시각에 만든다.
3. 엔진 테스트: caption 의 이모지와 줄바꿈이 도우미 입력에서 빠진다.
4. 엔진 테스트: 취소하면 도우미 프로세스가 끝나고 만들던 파일이 남지 않는다.
5. 엔진 테스트: 모델이 없으면 TTS 라우트가 409 와 받기 안내를 돌려준다.
6. 스파이크 S1 기록: 30초 대본 6장면 생성 시간 60초 이하, 최대 메모리, 사용자 청취 판정.
7. 패키징: `pnpm package` 로 만든 `.app` 에서 음성 만들기가 동작한다(GUI 확인, 스크린샷 경로 기록).
