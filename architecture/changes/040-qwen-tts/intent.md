## 문제
대본에 목소리를 넣으려면 사용자가 대본을 직접 읽어 녹음해야 한다. 녹음할 사람과 조용한 장소가 없으면 목소리가 들어간 쇼츠를 만들 수 없다. 앱은 결정 0017 에 따라 음성 합성(TTS)을 두지 않았다.

사용자 발의: "qwen tts 를 M6 24GB 이 머신에서 생성할 수 있어?", "이것도 별도의 plan으로 잡아야겠다."

## 기대 결과
- 사용자가 대본 장면의 자막으로 한국어 음성을 만든다. 만든 음성은 목소리 트랙에 장면 시각에 맞춰 들어간다.
- 음성 생성은 이 Mac 안에서 Qwen3-TTS 로 한다. 외부 API 와 API 키를 쓰지 않는다.
- 판정 기준 후보(하나를 고른다, 열린 질문 1):
  1. 30초 분량 대본(6장면)의 음성을 Apple M6 24GB 에서 60초 안에 만든다.
  2. 한국어 청취 확인에서 사용자가 "녹음 대신 쓸 만하다"고 판정한다.
  3. 만든 음성을 whisper 로 받아 적었을 때 대본과 글자 일치율이 95% 이상이다.
- 범위 밖: 다른 사람 목소리 복제, 실시간 재생 중 합성, 업로드, Intel Mac.

## 영향 범위
- 사용자: 대본 화면·편집 화면에서 음성을 만드는 사용자. 설정 화면의 모델 받기.
- 시스템: Node 엔진(새 작업과 라우트), 새 네이티브 도우미 실행 파일, 모델 받기(약 1.5~4.5 GB), 타임라인 목소리 트랙, 앱 패키징·서명.
- 외부 연동: Hugging Face 에서 모델 가중치를 받는다. 받은 뒤에는 네트워크를 쓰지 않는다.
- 진행 중인 변경: 039-script-voice 가 대본에 이모지를 허용한다. 음성으로 바꿀 때 이모지를 읽지 않아야 한다.

## 제약
- 결정 0017 의 "음성 합성(TTS)은 없다"를 대체해야 한다.
- 앱에는 Python 런타임이 없다(결정 0007·0008). 앱 구조는 Tauri + Node sidecar 이고 Apple Silicon macOS 만이다(결정 0001).
- 모델 파일은 앱과 레포에 넣지 않는다. 사용자가 받기를 고를 때 받는다(0007 과 같은 방식).
- 라이선스: Qwen3-TTS 코드와 가중치는 Apache-2.0 이다(GitHub README, Hugging Face 모델 카드 확인). Swift 포트 swift-qwen3-tts 는 MIT 다.
- 메모리: 통합 메모리 24GB 안에서 앱·Remotion·codex 와 함께 돈다.

## 열린 질문
1. 기대 결과의 판정 기준을 어느 것으로 정하는가.
2. 음성을 대본 장면 단위로 만드는가, 자막 클립 단위로 만드는가.
3. 음성이 장면 길이보다 길면 장면을 늘리는가, 음성을 그대로 두고 경고하는가.
4. 화자는 프리셋 화자 "Sohee"(유일한 한국어 원어민 프리셋)만 쓰는가, 다른 화자와 말투 지시(instruct)도 여는가.
5. 사용자 본인 목소리 복제(Base 모델, 3초 참고 음성)를 넣는가.
6. 실행 방식은 Swift 도우미(swift-qwen3-tts, MLX)인가, Python(mlx-audio)인가.
7. 모델은 1.7B CustomVoice(한국어 WER 1.741)인가, 0.6B CustomVoice(한국어 WER 3.053, 더 작음)인가.
