## 문제
기본 프롬프트(대본, 캐러셀 「주제로」·「영상으로」)는 앱 코드 안에 있다. 기본 프롬프트를 고치면 앱 릴리스(빌드·서명·공증, 10분 이상)를 다시 해야 사용자에게 간다. 053·054 뒤 같은 날 문서가 다시 바뀌어 0.3.5·0.3.6 을 연달아 냈다. 프롬프트는 자주 바뀌는데 갱신 비용이 앱 릴리스와 같다.

## 기대 결과
사용자 지시 원문: "기본 프롬프트를 릴리즈 페이지에 두는게 어떨까? 프롬프트 기본값을 릴리즈 깃에 두고 사용자가 수정한거면 그냥 두고, 기본값으로 돌리기 혹은 기본값일때는 릴리즈 페이지에서 프롬프트가 업데이트되면 자동으로 업데이트되게끔."

- 기본 프롬프트 세 개를 GitHub Release(`smpbrighton/u3`)에 둔다. 앱 릴리스 없이 그것만 갱신할 수 있다.
- 기본값을 쓰는 사용자, 또는 「기본값으로」를 누른 사용자는 새 기본값을 자동으로 쓴다. 판정: 기본 프롬프트를 올린 뒤 설치본을 다시 시작하면(실행 중이면 6시간 안에) 설정의 프롬프트와 생성에 쓰는 프롬프트가 새 본문이다.
- 프롬프트를 고친 사용자의 본문은 바뀌지 않는다.
- 범위 밖: 말투·성격 설정, 「주제 다듬기」 프롬프트, 이미지 생성 지시문, 형식 규칙(JSON 스키마 안내). 이것들은 앱 코드에 남는다.

## 영향 범위
- 사용자: 설정 「대본」의 대본 프롬프트, 설정 「이미지 생성」의 캐러셀 기획 프롬프트 두 개.
- 엔진: 기본 프롬프트를 받고 캐시하는 부분, 프롬프트 API 세 개, 대본 생성·캐러셀 기획 경로.
- 릴리스: 기본 프롬프트를 올리는 스크립트, `release.sh`.
- 외부 연동: GitHub Release 다운로드(공개 레포, 토큰 없음).

## 제약
- 네트워크가 없거나 받기에 실패해도 생성은 동작해야 한다.
- 앱의 JSON 스키마와 맞지 않는 프롬프트를 쓰면 안 된다. 옛 앱 버전도 깨지면 안 된다.
- 앱 업데이트 확인 주소(`releases/latest`, 결정 0021)를 바꾸지 않는다.
- 049(Windows 빌드, 미병합)가 `release.sh`·`system.ts`·`Settings.tsx` 를 바꾼다.

## 열린 질문
- 어디에 두는가: 고정 태그 prerelease 의 자산, main 브랜치 raw 파일, 번호별 prerelease 중 무엇인가.
- 서명이나 hash 검사가 필요한가.
- 언제 받는가.
- 사용자가 고친 상태에서 기본값이 바뀌면 알리는가.
- 개발 실행(`pnpm dev`)도 받는가.
