## 문제
uUu 는 웹 배포를 할 수 없다. 서버가 사용자 PC 의 `claude`·`codex` CLI 로그인 세션, ffmpeg, 헤드리스 Chrome, 로컬 파일을 쓰고 127.0.0.1 에만 묶이기 때문이다. 그래서 사용자는 레포를 받아 `pnpm dev` 를 실행해야 쓸 수 있고, 개발자가 아닌 사람은 쓰지 못한다.
uUu 에는 쿠팡 링크 시작, 음성 합성, 채널, 링크 허브, 캐러셀처럼 핵심이 아닌 기능이 많다. 이 기능들이 영상 편집이라는 핵심 흐름을 무겁게 한다.

## 기대 결과
U3 는 설치형 데스크톱 앱이다. 사용자는 설치 파일로 앱을 설치하고, 터미널 없이 아래 흐름을 끝낸다.

1. 사용자가 영상과 사진을 섞어 여러 개 넣는다.
2. 사용자가 대본 방식을 고른다.
   - 사용자가 간략한 대본을 쓰면 AI 가 대본을 만든다.
   - AI 가 영상의 중간중간 프레임 10장과 사진, 받아 적은 말소리를 보고 추천 대본을 쓴다.
3. 앱이 대본에 맞춰 사용자 영상과 짤방이 앞뒤로 붙은 스튜디오 화면을 보여 준다. 화면 아래에는 영상 편집 프로그램처럼 다중 트랙 타임라인이 있다.
4. 사용자가 타임라인에서 영상을 더 넣고, 자르고, 짤·효과음·자막을 고친다.
5. 사용자가 음성을 녹음하거나 오디오 파일을 넣고, 원본 소리를 목소리와 배경으로 나눠 조절한다. 말소리가 있으면 받아 적어(STT) 자막을 만든다.
6. 사용자가 결과를 mp4 로 내보낸다.

판정 기준:
- 설치 파일 하나로 설치한 앱이 `pnpm`·Node·Python 설치 없이 1~6 을 끝낸다.
- 앱 안의 기본 짤·효과음 라이브러리만으로 짤과 효과음을 고를 수 있다.
- 원격 AI 호출은 codex(모델 `gpt-6-luna`)와 Jev 만 한다. 로컬 모델(짤 검색·음성 분리·받아 적기)은 앱 안에서 돈다.

범위 밖:
- 음성 합성(TTS)
- 자동 업로드
- 채널 연동(잠시 뺀다)
- 링크 허브, 캐러셀, 쿠팡 링크 시작, 크롬 확장
- Claude CLI

## 영향 범위
- 사용자: 영상이나 사진을 직접 가진 숏폼 제작자. 앱을 설치해 쓴다.
- 시스템: 새 레포 U3. uUu 의 대본·짤 고르기·효과음·타임라인·Remotion 렌더 코드를 골라 옮긴다. uUu 레포는 바꾸지 않는다.
- 외부 연동: 사용자 PC 의 codex CLI 로그인 세션(모델 `gpt-6-luna`), TypeSafe Jev API.
- 배포물: 짤·효과음 기본 라이브러리를 앱에 넣는다. 저작권 검토는 이 변경의 범위가 아니다.

## 제약
- 앱은 Tauri + React 로 만든다.
- 원격 AI 는 codex 와 Jev 만 쓴다. Jev 는 기본으로 켜고, 개발자가 등록한 키를 그대로 쓴다.
- 프로젝트 이름은 U3 다.
- 화면설계는 아티팩트로 먼저 만든다. 사용자가 아티팩트를 확인하기 전에는 화면을 구현하지 않는다.
- 이 워크트리에서는 plan.md 까지만 만든다. 구현은 다른 곳에서 한다.

## 열린 질문
1. 결과물을 mp4 로 내보내는 기능이 범위에 들어가는가.
2. 원본 영상의 소리를 결과물에 남기는가.
3. 입력은 영상 1개, 사진 여러 장 중 무엇까지 받는가. 영상과 사진을 섞어 받는가.
4. AI 추천 대본은 첫 프레임 한 장만 보는가, 영상 전체에서 뽑은 여러 프레임을 보는가.
5. 대본 한 줄과 영상 구간을 누가 맞추는가.
6. Jev API 키는 누구의 키를 쓰는가.
7. 지원 OS 와 서명·공증 범위는 무엇인가.
8. 짤 검색 임베딩 모델(bge-m3, 2.1 GB)을 어떻게 배포하는가.
9. 짤·효과음 라이브러리를 둘러보는 별도 화면이 필요한가.
