# Intent: shortcut-settings
Author: sumin.p. Status: accepted.

## 문제
사용자는 “단축키는 설정에서 조정 가능하게 추가했으면 좋겠고”라고 요청했다. 지금 스튜디오는 자르기·재생·묶기·실행 취소·삭제 단축키를 코드에 고정했다. 사용자는 설정에서 자신이 쓸 키를 바꾸거나 기본값으로 돌릴 수 없다.

## 기대 결과
- 사용자는 설정에서 스튜디오 단축키의 현재 값을 보고 키 입력으로 바꾼다. 저장을 마치면 스튜디오는 새 키를 사용하고 바꾸기 전 키는 사용하지 않는다.
- 앱을 다시 실행해도 바꾼 키가 남는다. 사용자는 각 동작의 「기본값으로」를 눌러 기본 단축키를 복원한다.
- 앱은 다른 동작이 쓰는 조합과 예약된 글 편집 조합을 저장하지 않는다. 오류가 나면 이전 값을 유지한다.
- 한글 자판과 영문 자판에서 같은 물리 키는 같은 동작을 실행한다. 글 입력 중에는 글 입력이 스튜디오 편집을 실행하지 않는다.
- 스튜디오는 현재 단축키 목록을 라벨과 키 값으로 보여 준다. 목록은 사용자가 바꾼 값과 일치한다.
- 배포본에서 C/ㅊ 자르기가 동작하지 않는 결함은 별도 lite 변경 051 studio-shortcuts의 범위다. 이 변경의 완료 조건에 그 결함의 수정을 포함하지 않는다.

## 영향 범위
- 사용자: macOS Apple Silicon에서 스튜디오로 영상을 편집하는 사용자다.
- 화면: 설정의 구역 목록·단축키 입력 행과 스튜디오의 단축키 목록이다.
- 편집: 포인터 자르기, 재생 헤드 자르기, 재생·일시 정지, 묶기, 풀기, 실행 취소, 다시 실행, 삭제의 키 판정이다.
- 저장: 앱 전체 단축키 설정의 읽기·저장·복원이다. 프로젝트 파일과 타임라인 데이터는 바꾸지 않는다.
- 외부 연동: 없다. 키 입력이나 단축키 설정을 외부로 보내지 않는다.

## 제약
- 현재 편집 모델과 동작의 결과는 유지한다. 0016의 C·S 자르기는 기본값으로 남기고 사용자 재정의를 추가한다.
- 실제 조합 입력과 입력 요소·편집 가능한 요소·슬라이더 등에서 편집 단축키를 막는 보호를 유지한다. 한글 글자 대신 물리 키를 기준으로 기록하고 판정한다.
- 설정은 기존 자동 저장과 실패 처리 방식을 따른다. 단축키용 「저장」 버튼은 두지 않는다.
- 화면 글은 043-shadcn-redesign/pages.md 0절을 따른다. 설명문·도움말·예시 placeholder를 추가하지 않는다. 단축키 목록을 툴팁에 숨기지 않는다.
- 이번 범위는 기존 여덟 동작의 키 변경과 동작별 기본값 복원이다. 전역 단축키, 키를 차례로 누르는 조합, 사용자 매크로, 프로젝트별 설정은 추가하지 않는다.

## 열린 질문
- Q1. 설정은 엔진 settings.json과 테마처럼 localStorage 중 어디에 둘 것인가? 엔진 설정을 추천한다. 첫 화면 전에 동기로 적용해야 하는 테마와 달리 편집 설정을 기존 저장·검증 경로로 관리할 수 있다.
- Q2. 동작마다 몇 개의 키를 저장하고 기존 보조 조합(⌘M·⌃M·⌃Z)은 어떻게 다룰 것인가? 동작 id → 조합 하나를 추천하고 보조 조합은 없앤다. 충돌 검사·표시가 단순해지고 ⌘M 은 macOS 최소화와 겹친다.
- Q3. 설정과 스튜디오에서 목록은 어디에 둘 것인가? 설정의 새 「단축키」 구역과 스튜디오 툴바의 「단축키」 팝오버를 추천한다. 상시 목록은 타임라인 높이를 깎는다.
- Q4. “문자 입력과 겹치는 조합 금지”는 어디까지 적용할 것인가? 입력 중 실행 차단과 예약 조합 검사를 함께 추천한다. C·S·M 기본값을 유지하면서 글 편집 키를 보호할 수 있다.
- Q5. 기존 ⌘M 묶기와 macOS 창 최소화의 충돌은 어떻게 다룰 것인가? ⌘M 을 기본값에서 빼고 M 만 남기는 안을 추천한다. 시스템 예약 조합은 배정하지 못하게 한다.
