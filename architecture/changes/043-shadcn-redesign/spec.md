## 열린 질문에 대한 답
1. 판정 기준은 후보 1·2·3 을 모두 쓴다. 1 은 디자인 누락을, 2 는 SEED 잔존을, 3 은 구현과 디자인의 일치를 각각 막는다. 셋 중 하나만으로는 나머지 둘을 보장하지 못한다.
2. Tailwind CSS v4 를 도입한다. shadcn/ui 의 공식 경로이고, 부품을 일반 CSS 로 옮기면 shadcn 갱신을 따라가기 어렵다. 기존 `styles.css` 는 화면을 옮기는 만큼 줄이고 마지막에 지운다.
3. 사용자 지시("다크모드 설정할 수 있는거 설정에 꼭좀 넣어주고")에 따라 다크·라이트 두 테마를 만든다. 선택은 웹뷰 localStorage(`u3.uiTheme`)에 저장한다. 엔진 API 를 바꾸지 않고, 첫 화면 전에 동기로 읽어 깜박임이 없다. 설정의 선택지는 「다크」「라이트」「시스템 설정 따르기」 세 가지이고 기본값은 다크다. 기본값을 다크로 하는 이유는 영상 편집기의 관례이고 영상·이미지 색을 판단하기 쉬워서다.
4. 주황을 브랜드 강조색으로 유지하되 쓰는 곳을 좁힌다: 주요 동작 하나(내보내기·만들기·모두 받기), 선택 상태, 재생 헤드. 토글·스위치·슬라이더는 무채색이다.
5. Design 캔버스 타입 아티팩트 하나에 화면마다 아트보드(1440×900)를 두고, 보드마다 옆에 그 페이지의 핵심 명세를 붙인다. 같은 캔버스에 토큰·부품 보드와 대응표 보드를 둔다. 모든 보드는 토큰으로 그려서 다크·라이트 두 테마로 볼 수 있어야 한다. Design 타입이 테마 전환이나 보드 수를 받지 못하면 테마 전환 버튼이 있는 일반 HTML 페이지 하나로 바꾸고 그 사실을 plan 에 적는다.
6. 한 변경에서 한다. 사용자 지시에 따라 순서는 plan 승인 → 페이지별 기능 명세서(`pages.md`) → 사용자 검토 정지 → 디자인 아티팩트 → 사용자 승인 정지 → 화면 묶음별 구현 커밋이다. 두 정지는 사용자가 요구한 게이트이고 plan 의 순서에 명시한다. 디자인을 승인받기 전에는 앱 코드를 바꾸지 않는다.
7. Hugeicons 를 유지한다. 지금 아이콘을 바꿀 이유가 없고, shadcn 부품 안의 lucide 아이콘(펼침 화살표·체크·닫기)만 Hugeicons 로 바꾼다.

## 요구사항
1. 아티팩트 하나가 아래 「화면·상태 목록」의 모든 항목을 새 디자인으로 보인다. 대응표 보드가 항목마다 아트보드 이름을 짝짓는다.
2. 아티팩트에는 토큰 보드(색·글자 크기·간격·모서리·행 높이)와 부품 보드(버튼·입력·선택·슬라이더·스위치·탭·대화상자·메뉴·툴팁·토스트·속성 한 줄)가 있다.
3. 속성 패널(스튜디오 인스펙터, 캐러셀 패널, 설정 카드)의 한 줄 입력(슬라이더·스위치·선택·짧은 입력·색)은 「라벨 왼쪽, 컨트롤·값 오른쪽」 한 줄이고 높이 32px 이하다. 여러 줄 입력(대본 프롬프트·말투·성격, 말투 지시, 자막 글, 캐러셀 본문·이미지 지시문)과 미리보기는 패널 폭 전체를 쓰고 짧은 라벨 하나만 위에 둔다. 같은 뜻의 글을 두 번 쓰지 않는다.
4. 같은 줄의 컨트롤은 높이가 같다. 값 표시 위치는 앱 전체에서 한 가지다.
5. 주황 강조색은 「열린 질문에 대한 답」 4 의 세 곳에만 쓴다. 주황 바탕 위 글자는 두 테마 모두 4.5:1 이상이 되게 주황 값이나 글자 색을 정한다(지금 `#f60` 위 흰 글자는 2.94:1 이다).
6. 사용자가 디자인을 승인한 뒤, 앱의 모든 화면이 그 디자인대로 바뀐다. 기능·문구의 뜻·키보드 단축키는 바뀌지 않는다.
7. 구현 뒤 `src/` 에 `@seed-design`·`seed-design/ui` import 가 없고, `package.json` 에 `@seed-design/*` 가 없다.
8. 폰트는 앱에 들어 있는 Pretendard 를 쓴다. 외부 폰트 요청이 없다.
9. 설정에 「화면 테마」 구역이 있다. 「다크」「라이트」「시스템 설정 따르기」 중 하나를 고르면 앱 전체가 바로 바뀌고, 앱을 다시 열어도 유지된다. 기본값은 다크다. 「시스템 설정 따르기」는 macOS 의 모양 설정이 바뀌면 따라 바뀐다.
10. 모든 화면은 두 테마에서 글자 대비가 WCAG AA(본문 4.5:1) 이상이다.
11. 페이지마다 기능 명세서가 있다(`changes/043-shadcn-redesign/pages.md`). 항목은 페이지가 하는 일 한 줄, 다루는 대상, 대상별 핵심 동작(대상을 고르면 할 수 있는 일), 상태(빈 상태·진행 중·오류), 들어오고 나가는 화면이다. 지금 코드의 기능을 빠짐없이 옮기고, 동선을 바꾸는 곳은 바꾼 이유를 한 줄로 적는다. 예: 자막 클립을 고르면 그 자막의 글을 미리보기나 인스펙터 맨 위에서 바로 고치고, 레이어 스타일은 별도 묶음이다.
12. 화면 글 규칙: 입력 위아래 설명문, 도움말 문장, 설명형 placeholder 를 쓰지 않는다. 라벨은 꼭 필요한 곳에만 짧은 명사 하나다. 제목과 라벨이 같은 말을 반복하지 않는다. 빈 상태는 한 줄과 동작 하나다. 아이콘만 있는 버튼은 이름만 담은 툴팁과 접근 이름을 가진다. 오류는 무엇이 잘못됐고 어떻게 고치는지 한 줄로 쓴다.
13. 글꼴 굵기는 앱에 든 Pretendard 400·700 만 쓴다. shadcn 부품의 500·600 은 400·700 으로 바꾼다.
14. 최소 macOS 는 15 다(040 의 TTS 도우미가 이미 macOS 15 를 요구한다). Tailwind v4 의 Safari 16.4 요구를 만족한다.

## 설계
### 기술
- Tailwind CSS v4(`@tailwindcss/vite`)와 shadcn/ui 부품을 `src/ui/components/ui/` 에 둔다. 부품은 Radix primitives 위에 있다.
- 테마 토큰은 shadcn CSS 변수(`--background`, `--foreground`, `--muted`, `--border`, `--primary` 등)로 `src/ui/theme.css` 에 둔다. 라이트 값은 `:root`, 다크 값은 `.dark` 에 둔다. 앱은 `<html>` 의 `dark` class 로 테마를 바꾼다.
- 테마 선택은 엔진 설정 파일에 `uiTheme`(`dark`·`light`·`system`, 기본 `dark`)으로 저장한다. 첫 화면이 그려지기 전에 값을 읽어 깜박임 없이 적용한다. `system` 은 `prefers-color-scheme` 변화를 따른다. Tauri 창 배경색도 테마에 맞춘다.
- 밀도: 기본 컨트롤 높이 32px, 속성 한 줄 28~32px, 본문 13px, 패널 제목 12px 대문자 아닌 굵게, 모서리 6px.
- U3 전용 부품(`src/ui/components/u3/`): `PropertyRow`(라벨·컨트롤·값), `PropertySection`(접히는 묶음), `Toolbar`, `TrackHeader`, `EmptyState`, `StepNav`.
- `seed-design/` 래퍼와 `src/ui/studio/SeedControls.tsx` 는 마지막 단계에서 지운다.
- 공존 기간의 CSS 순서: SEED `all.css` 와 기존 `styles.css` 를 `@layer seed, legacy` 에 넣고, Tailwind 의 `@layer theme, base, components, utilities` 보다 앞에 선언한다. 그래야 옮긴 화면의 유틸리티가 이긴다.
- Tailwind preflight 는 앱 셸에만 적용하고 Remotion Player 영역(`.carousel-player`, 스튜디오 미리보기)에는 적용하지 않는다. 미리보기와 렌더 결과가 같은지 캡처로 확인한다.
- 토스트는 Sonner 를 쓰되 `next-themes` 를 쓰지 않고 앱의 테마 상태를 `theme` prop 으로 넘긴다.
- 창 배경색은 Tauri `setBackgroundColor` 로 테마에 맞춘다. `src-tauri/capabilities/default.json` 에 `core:window:allow-set-background-color` 를 더한다.
- `tauri.conf.json` 의 `bundle.macOS.minimumSystemVersion` 을 `15.0` 으로 둔다.
- 타임라인 편집기(`@xzdarcy/react-timeline-editor`)는 유지하고 그 CSS 만 토큰으로 다시 칠한다(결정 0016).

### 기능 명세서
- `pages.md` 는 화면·상태 목록의 묶음(공통, 영상 목록, 1 미디어, 2 대본, 스튜디오, 캐러셀, 설정)마다 한 절이다.
- 지금 기능은 코드(`src/ui/`)와 캡처 아티팩트에서 뽑는다. 명세에 없는 기능은 디자인과 구현에 넣지 않고, 지금 있는 기능을 명세에서 빼려면 사용자 검토에서 정한다.

### 아티팩트
- Design 타입으로 만든다. 보드 순서: 표지·원칙(화면 글 규칙 포함) → 토큰 → 부품 → 화면(목록 순서, 보드마다 핵심 명세) → 대응표.
- 화면 보드는 실제 데이터(지금 캡처의 프로젝트·캐러셀 이름과 문구)를 쓴다.
- 비교를 위해 대응표 보드에서 각 항목 옆에 지금 캡처 아티팩트의 해당 화면 이름을 적는다.

### 구현 순서(plan 에서 확정)
1. Tailwind·shadcn 기반과 토큰, U3 부품.
2. 공통 셸(사이드바·토스트·대화상자).
3. 설정 → 캐러셀 → 영상 목록·1 미디어·2 대본 → 스튜디오 순서로 화면 묶음별 커밋.
4. SEED 제거, 의존성 삭제.

## 우려 사항
1. 전면 개편은 모든 화면을 건드린다. 기능 회귀가 날 수 있다. 정책 소유자: 엔지니어링. 추천: 화면 묶음마다 `pnpm verify` 와 실제 화면 캡처를 남기고 커밋한다. 이유: 묶음 단위로 되돌릴 수 있다.
2. 두 테마를 모두 만들면 디자인과 확인 작업이 화면마다 두 배가 된다. 정책 소유자: 제품 책임자. 추천: 모든 색을 토큰으로만 칠하고, 화면마다 두 테마 캡처를 남긴다. 이유: 토큰 밖의 색이 섞이면 한 테마에서만 글자가 안 보이는 결함이 생긴다.
3. Design 타입 아티팩트가 아트보드 40개 이상을 한 캔버스에 담을 수 있는지 확인하지 않았다. 정책 소유자: 엔지니어링. 추천: 첫 단계에서 확인하고, 안 되면 일반 HTML 페이지 하나로 바꾼다.
4. 디자인 승인 전에는 구현하지 않으므로 이 변경 기간이 길다. 그 사이 다른 변경이 같은 UI 파일을 고치면 충돌한다. 정책 소유자: 제품 책임자. 추천: 이 변경 동안 다른 UI 변경은 이 변경 뒤로 미룬다.
5. 타임라인 「음성 만들기」 겹침 결함은 지금 0.2.2 에 있다. 정책 소유자: 제품 책임자. 추천: 이 변경에서 트랙 머리를 다시 만들며 고친다. 이유: 따로 고친 코드는 이 변경에서 다시 바뀐다.

6. 037(타이틀 바 내용)과 041(Jev 키 설정)은 설정 화면의 사용자 확인을 기다리는 상태다. 043 은 같은 카드를 다시 만들고, 041 plan 이 유지하기로 한 Jev 카드의 안내 문구는 요구사항 12 와 맞지 않는다. 정책 소유자: 제품 책임자. 추천: 0.2.2 에서 두 카드를 확인해 037·041 을 닫은 뒤 043 설정 구현을 시작한다. 안내 문구는 043 의 화면 글 규칙이 대체한다.
7. 최소 macOS 를 15 로 올리면 macOS 13·14 사용자는 설치하지 못한다. 정책 소유자: 제품 책임자. 추천: 올린다. 이유: 040 의 TTS 도우미가 이미 macOS 15 를 요구한다.
## 검증 기준
1. 아티팩트의 대응표가 「화면·상태 목록」 전부를 아트보드와 짝짓는다. 빈 칸이 없다.
2. 사용자가 아티팩트를 승인한다(plan 게이트).
3. `pnpm verify` 가 종료 코드 0, 마지막 줄 `✓ verify passed` 다.
4. `grep -rn "seed-design\|karrotmarket" src index.html package.json tests` 결과가 0줄이고 `seed-design.json`·`seed-design/` 이 없다.
5. 화면 묶음마다 구현 캡처를 남기고, 아티팩트 보드와 나란히 놓은 비교 페이지를 사용자가 승인한다. 비교에는 042 의 캐러셀 인스펙터 넘침 없음과 미리보기·렌더 결과 일치를 포함한다.
6. 「음성 만들기」 겹침: 트랙 머리를 다시 만들기 전에 트랙 머리 항목이 칸 폭을 넘지 않음을 단언하는 실패 테스트를 먼저 커밋한다.
7. SEED 소스 문자열을 단언하던 테스트(`tests/ui/studio-toolbar.test.ts`, `tests/ui/update-components.test.tsx`, `tests/ui/timeline-layout.test.ts` 등)는 같은 동작을 새 부품 기준으로 단언하게 고친다. 동작 단언을 지우지 않는다.
8. `pages.md` 를 사용자가 검토해 확정한다(사용자 게이트).
9. 네트워크를 끈 상태에서 앱 글꼴이 Pretendard 로 보인다.
10. 테마 테스트: 설정의 세 선택지가 저장·복원되고 `<html>` class 가 바뀐다. `system` 은 `prefers-color-scheme` 변화에 따라 바뀐다.
11. 화면 묶음마다 다크·라이트 두 캡처가 있다.
