## 문제
U3 는 클립·타임라인·속성 패널을 한 화면에서 다루는 데스크톱 편집기인데, UI 는 모바일 우선 디자인 시스템 SEED(결정 0001)로 만들었다. 그래서 화면이 너저분하고 직관적이지 않다.

사용자 발의: "가볍고 모바일중심의 seed-design 이 어울리지 않나 싶은데. shadcn으로 바꾸는건 어떻게 생각해? seed-design은 input 위아래로 글이 너무 많고 직관적이지 않은것 같은데", "shadcn으로 전면 디자인개편 시작하자 디자인은 한곳도 뺴놓지않고 아티팩트 하나에 모두 담겨야해", "다크모드 설정할 수 있는거 설정에 꼭좀 넣어주고", "모든 페이지의 기능명세서를 만들고 각 페이지에 맞는 페이지로, 예를들어 자막을 클릭하면 자막별로 자막을 수정할 수 있는게 지금은 직관적이지 않거든", "input이나 여타 어딘가에 description이나 label 같은걸로 설명을 더하는건 정말 ai slop이라고 생각하거든. 핵심 기능만 있고 핵심 명세만 있게끔 해야해".

현재 화면에서 확인한 증상(캡처: https://claude.ai/artifact/Ci7ioBeQeMfPy1R6sijYjn):
- 입력 위아래에 라벨·설명 글이 많고, 제목과 토글 라벨이 같은 말을 반복한다(설정 「자동 알림음」).
- 같은 줄의 선택 상자와 버튼 높이·기준선이 다르다. 값 표시 위치가 화면마다 다르다.
- 편집 화면 속성 패널은 속성 하나가 세로 60~70px 를 차지해 밀도가 낮다.
- 타임라인 트랙 이름 칸에서 「음성 만들기」 버튼이 트랙 이름과 겹친다.
- 주황 강조색을 주요 버튼·토글·스위치에 모두 써서 무엇이 중요한지 흐려진다.

## 기대 결과
- 모든 페이지에 기능 명세서가 있다. 명세서는 페이지가 하는 일, 다루는 대상, 대상을 고르면 할 수 있는 동작을 정한다. 예: 자막 클립을 누르면 그 자막의 글을 바로 고친다.
- 모든 화면과 상태의 새 디자인이 아티팩트 하나에 들어 있다. 빠진 화면이 없다. 디자인은 그 페이지의 명세를 따른다.
- 화면에는 핵심 기능과 핵심 명세만 있다. 입력 위아래 설명문·도움말 문장·설명형 placeholder 가 없다.
- 앱 UI 가 SEED 대신 shadcn(Radix 기반 부품) 위에서 그 디자인대로 동작한다. 기능은 바뀌지 않는다.
- 사용자는 설정에서 화면 테마(다크·라이트)를 고른다. 아티팩트는 모든 화면을 두 테마로 보인다.
- 판정 기준 후보(열린 질문 1):
  1. 아티팩트의 대응표가 spec 의 화면·상태 목록 전부를 디자인과 짝지어 보인다(누락 0).
  2. 구현 뒤 `src/` 에서 `@seed-design` 과 `seed-design/ui` import 가 0건이다.
  3. 화면마다 구현 캡처와 아티팩트 디자인을 나란히 놓고 사용자가 승인한다.
- 범위 밖: 테마 설정 말고는 기능 추가·삭제, 영상·캐러셀 결과물(Remotion 렌더)의 모양, Windows·Intel 지원.

## 영향 범위
- 사용자: 앱의 모든 화면(영상 목록, 1 미디어, 2 대본, 스튜디오, 캐러셀, 설정, 대화상자·메뉴·알림, 업데이트 표시).
- 시스템: `src/ui/` 전체(SEED 를 쓰는 파일 18개, `styles.css`, `src/ui/studio/SeedControls.tsx`), `seed-design/` 래퍼, UI 테스트의 SEED mock, 빌드 설정(Tailwind 도입 시 Vite 설정).
- 결정: 0001 의 "UI 는 React + Vite + SEED" 를 대체한다.
- 외부 연동: 없음. 폰트·아이콘은 앱에 넣는다.

## 제약
- 기능·데이터·엔진 API 는 바꾸지 않는다. 동선(어디서 무엇을 고치는가)은 기능 명세서에 따라 바꿀 수 있다. 기존 테스트의 동작 단언은 유지한다.
- 앱은 오프라인에서도 같은 모양이어야 한다. 폰트를 런타임에 외부에서 받지 않는다.
- 웹뷰는 macOS WebKit(Tauri)이다.
- 라이선스: shadcn/ui·Radix·Tailwind 는 MIT 로 알고 있다. 구현 전에 각 저장소의 LICENSE 로 확인한다.
- 디자인 산출물은 아티팩트 하나다. 구현은 그 아티팩트를 기준으로 한다.

## 열린 질문
1. 기대 결과의 판정 기준을 어느 것으로 하는가(후보 1~3, 복수 가능).
2. Tailwind 를 도입하는가, shadcn 부품을 일반 CSS 로 옮기는가.
3. 테마 설정의 선택지와 기본값은 무엇인가(다크·라이트·시스템 따르기).
4. 강조색은 지금의 주황을 유지하는가.
5. 아티팩트는 Design 캔버스 타입인가, 일반 HTML 페이지인가.
6. 디자인 확정과 구현을 한 변경에서 하는가, 디자인 승인 뒤 화면 묶음별로 나누는가.
7. 아이콘은 지금의 Hugeicons 를 유지하는가, shadcn 기본 lucide 로 바꾸는가.
