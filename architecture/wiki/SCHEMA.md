# wiki SCHEMA

이 폴더는 LLM이 유지하는 이해의 층이다. 사람은 읽고 질문하며, 페이지는 LLM만 쓴다. 조작은 `/smp:wiki ingest|query|lint`.

## 층
- 원본(불변): 코드, git log, `../INTENT.md`, `../changes/`, `../decisions/`. 위키는 이것들을 절대 고치지 않는다.
- 위키(파생): `pages/` 아래 entity·concept·answer 페이지. `index.md`가 목록, `log.md`가 이력.
- 스키마: 이 파일. 무엇이 어디 있고 어떻게 유지하는지.

## 규칙
1. 모든 주장에 출처 ref를 붙인다. `changes/NNN-slug/spec.md`, 코드 경로, 커밋 해시 중 하나. ref 없는 주장은 lint 실패다.
2. 충돌하면 코드와 원본 문서가 이기고 위키가 진다. 위키는 캐시다.
3. 결정은 여기에 없다. 결정이 어디 있냐고 물으면 답은 항상 `../decisions/`다. 위키는 왜 그렇게 됐는지와 어떻게 엮이는지를 가진다.
4. "코드에서 못 찾음"은 유효한 값이다. 빈칸을 채우지 않는다.
5. 이력은 `log.md`와 git에만 있다. 페이지 본문에는 날짜 서사를 쓰지 않는다.
6. 새 페이지는 index에 넣고 관련 페이지에서 링크한다. 들어오는 링크가 없는 페이지는 고아다.

## 페이지
- 경로: `pages/<kind>-<slug>.md`. kind는 `entity`(모듈·서비스·테이블·외부 시스템) · `concept`(규칙·흐름·용어) · `answer`(query에서 남길 가치가 있던 답).
- 형식: `# 제목` → `## 요약`(세 문장 이내) → `## 내용` → `## 관계`(다른 페이지 링크) → `## 출처`(ref 목록).

## 조작
- ingest: 라운드 마감마다. 이번 라운드의 커밋에 든 `changes/` 문서와 코드 diff를 읽고 영향받은 페이지를 갱신하고 index를 고치고 log에 한 줄. 위키 변경은 같은 라운드 커밋에 포함한다.
- query: 질문에 index → 페이지 → 원본 순으로 답하고 출처를 인용한다. 재사용될 답은 answer 페이지로 저장한다.
- lint: 페이지 간 모순, 코드에서 사라진 ref, 고아 페이지, 누락된 교차 링크, 본문에 서술된 결정(규칙 3 위반)을 찾는다. 위키가 스스로 고치지 않고 `changes/NNN-wiki-lint/intent.md` 초안으로 올린다.

## log 형식
`## [YYYY-MM-DD] ingest|query|lint | 제목` 한 줄 뒤에 바뀐 페이지 목록. 추가 전용. `grep "^## \[" log.md | tail -5` 로 최근 5건.
